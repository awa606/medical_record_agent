## V2阶段反馈（历史）

用户指出V1“字太小，而且我还是偏向于原有的三栏的前端”。因此恢复转写、病历、临床提示三栏；正文18px、主要按钮16px、辅助信息至少14px。右栏切换证据不影响病历位置。此处的三栏指三个业务区域，导航保留在其外侧。

V2已在原8767端口展示；用户最新反馈为“方向对，还需调整”。**Visual Review：NEEDS ADJUSTMENT；Research Gate：NEEDS MORE EVIDENCE；Design Gate：NEEDS VALIDATION。** 等待具体调整点，不因方向认可而固定截图或开始业务接入。

68项样稿布局/交互检查通过；首次4项失败来自试听按钮可访问名称重复，修复后完整重跑，失败结果保留。新增字号下限和打开证据后栏位不变检查。Edge状态读取成功，截图通道超时；真实缩放和跨浏览器完整验收尚未成立。

H-UI-02：恢复常驻三栏、提升字号能改善用户阅读体验且保持布局稳定。技术检查通过，用户仅认可方向，实验尚未满足产品通过条件。16项/99h、日期、依赖和5.1 BACKLOG不变。

证据：[V2报告](../evidence/20260923_alpha51_visual_preview_v2.json)、[V2样稿](../prototypes/doctor-workspace-v2/README.md)。V1目录保持原样；不改生产代码。

## Research：已有资产、候选与最小实验

RQ1：保留现有工作台是否能够改善布局而不改变业务契约？RQ2：怎样阻止“功能通过但界面退化”再次发生？

| 候选 | 依据 | 结论 |
|---|---|---|
| 继续叠加旧CSS补丁 | `doctor.css`与`doctor-ui-v2.css`同时加载；v0.7.6/0.7.7记录了新增覆盖规则 | 无法形成稳定布局责任边界，未采用 |
| 隔离样稿，批准后有限适配现有API | 已有3.1状态派生、3.3编辑/审核和4.2Revision；原生HTML/CSS/JS即可演示 | 当前候选；V1视觉被否决，尚未批准生产接入 |
| 更换前端框架或录音库 | 未发现必须换框架才能解决的缺陷，迁移会扩大回归面 | 不采用 |

外部工具复用Playwright官方截图比较；测试依赖锁定`@playwright/test 1.60.0`（Apache-2.0），仅在开发测试使用。采用官方支持的截图机制，不自研图片比较算法。其运行环境敏感性要求固定OS、浏览器及字体。

H-UI-01：病历主视图与按需侧栏能保持主要动作可见、消除横向溢出，并获得用户对阅读与操作体验的认可。

输入：匿名固定病例，11种场景，4种视口。实测：64项几何/交互检查通过，用户视觉判断为“不认可，需要重新调整布局”。结论：**技术可运行，产品目标未达成**；等待具体反馈或参考设计后重做样稿，不重复凭内部测试宣布成功。

固定七问：已有原生工作台和官方截图工具可复用；旧整体布局不能原样复用；最大风险是测试与医生体验脱节；最低成本验证为隔离可点击样稿；证据为本轮64项结果及用户否决；最终REUSE/ADAPT/BUILD在具体样稿认可前不填写；回退只移除未接入的样稿，不影响现有业务。

## 15项设计检查

| 项目 | 本轮边界与结果 |
|---|---|
| Goal | 清晰、可操作、稳定的医生工作区；用户视觉验收尚未通过 |
| Deliverables | 隔离样稿、测试工具、否决记录；未来为业务接入、三路径报告及可恢复冻结包 |
| Input / Output | 合成示例输入→样稿状态与截图；不读取患者数据、不产生病历 |
| Constraints | 原生前端、现有品牌/导航/五步；不改API、数据库、Provider、安全阈值 |
| Largest uncertainty | 具体布局不符合用户预期；V1已经被否决 |
| PBS | 版式与交互、截图回归、真实E2E、归档恢复四类交付物，逐层验证 |
| Architecture | 样稿隔离静态服务→仅页面内状态；批准后才接业务状态/现有接口 |
| Responsibilities | 样式管布局，渲染管展示，现有业务层管状态/请求；当前不实施后两者接入 |
| Interfaces | 公共接口零变更；保留原有role PATCH、Review/Approval/Export和知识检索契约 |
| WBS | 5.1前置视觉修正，不新增任务；正式三路径测试尚未开始 |
| Dependencies | 3.3、4.2有效DONE；当前具体视觉方案未获认可 |
| Critical path | 同轮Project Planner快照显示5.4为零浮时；不另算CPM。硬件延期与容量告警保留 |
| Risks | R04体验/状态不一致，R08旧部署与代码不一致，R11额外返工；均不关闭 |
| Minimal validation | 样稿→用户确认→固定图片基线；本轮停在用户否决，重新收集反馈 |
| Milestones / Acceptance | 视觉认可+真实三路径3/3+隔离断网恢复才可冻结；当前均未完成 |

固定五问：按视觉、业务、恢复拆开便于定位；备选是继续旧CSS或换框架，本轮均不采用；最可能失败是内部检查代替真实体验；最小验证是可点击样稿；完成证据必须同时含用户确认、真实业务操作和恢复报告。
