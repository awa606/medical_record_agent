## 已落实的空间与操作规则

- 桌面顶栏48px、患者区至少56px、进度36px；三栏间距12px，宽度24%/54%/22%。
- 导航16px、正文17px、转写16px、模块标题18px；4/8/12/16/24px间距层级。普通字段白底细分隔线，红色保留给冲突。
- 录音控制位于转写栏，活动状态仅暂停/停止/取消，停止后才显示试听与提交。已有录音状态及失败重试逻辑不替换。
- 有病历时普通下一步说明不再重复常驻，页尾保留编辑/保存/审核/导出及其原禁用条件；异常恢复不隐藏。
- <1280px参考按需打开；<1024px转写也按需打开。移动原DOM避免两套状态，Esc关闭、焦点回到入口，编辑缓冲不丢失。
- 不靠缩小病历正文字号维持三栏。窄屏“确认说话人身份”入口和就诊状态仍可见。

## 固定五问

1. 为什么这样拆：让持续阅读和编辑集中在病历中，转写和参考各自承担核对，不重复主操作。
2. 替代方案：仅改字号不能修复高度/宽度分配；全新框架和另一份样稿会扩大维护差异。本次复用现有DOM。
3. 最大风险：CSS和隐藏控件影响原录音/焦点恢复；必须跑真实页面测试，不能只验证孤立样稿。
4. 最小成本验证：固定匿名病例加六种状态，使用本地demo/mock API；不需要重新运行模型。
5. 如何证明：几何测量、同病例截图、交互测试、用户确认分别保留；未知缩放或新版本恢复不冒充已通过。

ASSUMPTION A01：本轮只制作候选。A02：验收页切场景会重置合成前端状态，不用来保存临床资料。A03：已有真实三路径和r6仅为历史证据。

**Design Gate：PASS（已授权候选实现）；Visual / Release Gate：NEEDS VALIDATION。**
