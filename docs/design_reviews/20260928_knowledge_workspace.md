# 5.1 知识目录与版本核验设计增量

- 决策：ADAPT；复用R-4.1与20260917设计已验收的管理、权限和版本接口。当前分支 codex/alpha51-demo-visual-e2e；起点64d52c5。
- 用户批准：2026-09-28“让知识库可见、可查”计划；范围为发热/呼吸做深，正式16项99h不变。
- 目标/交付：管理员默认看到资料目录、检索验证、索引状态；医生继续使用现有查依据。交付界面、来源覆盖表、独立版本评测和手册增量。
- 输入/输出：现有管理员文档/健康接口、医生检索和指定版本测试接口 → 目录、元数据、命中原文与引用。原文使用既有 excerpt 字段，不创建新全文API。
- PBS与模块：静态UI负责呈现/筛选/键盘；knowledge API保持认证与校验；store保持内容/版本/启停事实；离线副本负责版本迁移验证；PM记录实际证据。
- 边界/约束：不改公共API、数据库结构、ASR/LLM、安全阈值和医生三栏。没有新框架、下载、训练、采购或疾病扩展。
- 接口：目录GET documents、详情使用既有文档元数据；PATCH仅既有来源字段；导入POST默认停用；启停沿用现有POST；默认测试调用医生retrieve，指定候选调用admin/test-search；401/403/404/503按原语义处理。
- 状态与失败：服务失败不显示为空库；无结果与失败分开；检索中禁用重复提交；元数据保存失败保留表单。关闭与Esc使用原生dialog，返回触发控件。来源URL经过http(s)白名单、动态字段全部转义。
- 数据所有权：标题、适用范围等source级字段影响该来源全部版本；在编辑表单说明。内容/版本/SHA不能PATCH。计数包含历史，不等于当前检索质量。
- 最大未知：新版流感能否命中预期页码且不损坏历史引用。用一致性副本先固定10条页码查询再运行；不调参、不改旧40条标签。
- 版本迁移：2020/2025是不同source；副本启用2025且显式停用2020。页码Recall@5≥90%、引用100%、非流感无退化、停用泄漏0、业务/历史片段不变后才有资格切换运行环境。失败保留2020及停用2025。
- WBS/依赖：5.1 VERIFY中限定缺陷修正，4.1不重新计完成；5.3须待5.1放行。正式日期/工时/依赖不变，返工窗口记R11。
- 关键路径：沿同轮Project Planner共享快照，不另算排程；当前优先5.1，完整M4仍受硬件延期约束。
- 风险：目录美化不能解决Qwen主诉冲突；来源级元数据可能误述历史索引，因此范围同时注明旧/新版本；新版本查询失败不靠改标签通过；模拟数据不等于临床真值；不将当前版本历史证据当作新的稳定冻结。
- 回退：旧镜像与env保留；数据库变更仅既有API来源元数据并记录前值；不覆盖业务库。新版本若不通过不执行运行库启停。
- 验收：真实按钮导入/筛选/编辑/检索/启停、三分辨率、Esc/焦点、服务故障、权限、真实excerpt展示、40+10查询、完整pytest/前端/CI；新SHA流程与恢复未全齐仍VERIFY。

## 固定五问与Gate

1. 为什么这样拆：数据事实、检索与前端操作独立验证，避免视觉改动掩盖数据或模型失败。
2. 替代方案：原样大表单藏住资料；新框架/全文服务增加范围，因此拒绝。
3. 最可能失败：新版页码相关性、source级元数据影响历史、生产环境与页面版本不一致。
4. 最小验证：一份真实现有资料的目录→详情→检索及独立数据库副本版本实验。
5. 如何证明：真实API按钮证据、引用/停用/权限指标、版本指纹与保留失败；测试数量不替代三路径/恢复。

管理交互沿用既有Research PASS / ADAPT；本增量设计接口与验收明确，可以实施。**资料版本提升NEEDS VALIDATION**，由实际评测判定，不能随UI交付预写PASS。
