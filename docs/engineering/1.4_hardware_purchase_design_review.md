# WBS 1.4 · Minimal Hardware Purchase Gate Design Review

- Date: 2026-09-15
- Research input: [`R-1.4-Hardware-Integration`](../research/R-1.4-Hardware-Integration.md)
- Selected decision: `ADAPT`
- Purchase decision: `BORROW-FIRST`
- Design Gate: `PASS`

## 1. Goal

用最少充分证据决定是否进入 Jetson 实机验证，并冻结 Alpha 硬件设计基线。

## 2. Deliverables

两套BOM、报价证据、主备外壳结论、五项采购Gate、机器可读Gate记录、Obsidian同步和GitHub状态镜像。

## 3. Input / Output

输入为官方机械/接口资料、公开下单页、既有6.5GiB资源Spike和现有资产清单；输出为可复核的 `BORROW-FIRST` 决策与后续实机验证边界。

## 4. Constraints

预算上限3000元；不采购、不改生产代码、不运行新模拟、不做最终CAD；开发机证据不能替代Jetson实机。

## 5. Maximum Uncertainty

公开低价成交渠道不存在两份完整报价，CASE-A的J11单面2280 NVMe实际厚度/热垫净空也未实测。二者都通过借机与交易前复核关闭。

## 6. PBS

边缘计算套件、运行存储、安装结构、LAN与音频能力；电脑、路由器、网线和六麦作为Existing Asset。

## 7. Architecture

`PC Browser / USB Audio → LAN → Jetson(FastAPI → ASR → release → LLM → SQLite/files)`。ASR与LLM采用串行生命周期，避免已观察到的共驻留OOM。

## 8. Module Boundaries

硬件采购门只判断是否值得进入实机验证；目标容器、Provider和性能验收属于1.2/1.3，最终外观属于后续阶段。

## 9. Interfaces

PC侧USB/UAC与浏览器；网络侧GbE/HTTP；Jetson侧19V、J11 M.2 Key-M、USB、DP与恢复USB-C。现有六麦型号待核，但不阻塞计算盒借机。

## 10. WBS

不新增任务。1.4交付Design Baseline和采购判断；1.2继续承担真实设备Bring-up/运行环境；1.3只提前做Research。

## 11. Dependencies / Critical Path

保持 `1.1 → 1.4 → 1.2 → 1.3` 和既有20条技术依赖。1.4仍受1.1有效完成门禁约束，因此本轮不绕过插件把它推进到READY。

## 12. Risks

- 成本：公开渠道价格与建议价偏离，使用BORROW-FIRST限制损失。
- 机械：单面NVMe净空待实物验证，CASE-A为主选、开源STEP为退路。
- 技术：8GB共驻留OOM已确认，串行隔离作为设计约束；真实ARM/CUDA和热稳定性待借机。
- 音频：六麦型号缺失，后续核对USB/UAC和浏览器行为。

## 13. Minimal Validation

只需借用一台Orin Nano Super 8GB，在48小时内按SSD→JetPack/CUDA→容器→ASR→LLM→内存/温度/稳定性验证，并实测CASE-A的NVMe空间。

## 14. Milestones

本轮里程碑是Research Gate PASS、Design Gate PASS和Hardware Purchase Decision形成；M1–M4日期和验收标准保持不变。

## 15. Acceptance

- 两套BOM明确记录缺失报价字段，没有把建议价当成交价。
- 五项Gate与BORROW-FIRST判定一致。
- 机械适配只报PARTIAL，不伪造FIT。
- 1.1 VERIFY、1.2 BLOCKED、1.3 BACKLOG保持；1.4在依赖不满足时不越权推进。
- 不采购、不改业务代码、不宣称Jetson PASS。

## Fixed Five Questions

1. **如何拆分？** 报价、BOM、机械、技术风险和同步镜像分别验证，采购门不承担实机验收。
2. **有哪些替代？** 直接购买、先借机、拒绝平台；外壳可用CASE-A、开源STEP或开放支架。
3. **最可能失败在哪里？** 低价渠道不可成交、SSD底部净空不足、ARM64依赖不兼容或8GB下LLM时延不可接受。
4. **最低成本验证是什么？** 借机48小时分层验证，交易前再刷新报价。
5. **如何证明完成？** 用公开来源快照、机器可读Gate、Obsidian工程快照、Git提交SHA和实机报告形成证据链。

## Gate

**PASS**

设计边界、回退、验收和后续最小实验均明确。PASS只授权本轮文档、项目同步和状态镜像，不授权采购或目标设备实现。
