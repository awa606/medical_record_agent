# 部分草稿、医生处置与窗口内帮助：研究及增量设计评审

## 研究结论与证据

基线为859edb0，活动运行版为b6c8158；两者不能混称。用户已明确批准：近期交付稳定的医生审核流程，模型首次输出质量独立报告，不以人工修订冒充模型正确。正式16项、99h、硬件延期和5.1/5.3验收条款保持不变。

已知失败：冲突值仍进入正文；仅检查非空值会把全冲突当作草稿；人工修正后损坏引用仍可能阻断；帮助用新标签页及系统浏览器打开。上一轮内存回放定位这些问题，本轮隔离Spike验证原Revision证据不变、明确人工来源可重新审核、同源iframe可显示及跳转现有手册。证据为本地`.artifacts/partial-draft-20261012/research-spike.json`和截图，无模型调用；浏览器Spike使用独立测试库和UI fixture，不是临床或真实模型验收。

| 候选 | 适配与代价 | 决策 |
| --- | --- | --- |
| 现有字段状态、Revision、审核和抽屉 | 已有字段粒度；新增明确处置及正文投影；无新生产依赖 | ADAPT |
| 忽略全局安全错误或从坏JSON中抢救文字 | 容易把否定、主体、证据错误写入正式病历 | 拒绝 |
| 引入新抽取框架或重写桌面客户端 | 不解决本次确定性缺陷，增加迁移、重试与发布变量 | 拒绝 |

别人已解决结构约束与应用窗口封装；本项目可直接复用其机制。最大风险是将医生处置混记为模型正确、清除原始证据、iframe导航导致丢稿。最低成本验证为已有响应回放、补录链回归与同源嵌入；适配证据已取得，Research PASS仅针对上述机制。失败回退859edb0代码及8798原镜像/一致性备份，不删除历史。

## 增量设计

| 评审项 | 本批约定 |
| --- | --- |
| Goal、交付物 | 医生能继续处理校验通过字段；拒绝内容隔离；补录保存可审核；帮助不离开工作窗口 |
| 输入输出 | 原字段/证据/当前Revision→七字段草稿投影与待核对项；医生处置→新Revision及来源记录 |
| 约束、未知 | 固定现有模型/提示词/采样，无自动重试；最大未知为真实响应下可用字段数及人工处置流程，不承诺模型质量改善 |
| PBS与架构 | Generator负责字段校验；renderer负责正文投影；review API负责可信医生处置及版本事务；前端负责编辑/详情/帮助，不改数据库表 |
| Owned Data | 模型原始字段留旧Revision；处置历史写现有result_json/审计；前端未保存选择仅在编辑状态；帮助复用白名单文件 |
| 接口 | review可选manual_takeover_fields、source_corrected_fields，默认空；不兼容字段/重复/交叉/无实际变化返回422；旧Revision409；权限沿用既有接口 |
| 处置规则 | 根据原文修正必须提供合法SourceSpan并运行原语义校验；医生补录要求实际内容变化，清除本版本自动证据绑定，记录旧值/引文和人工来源，不能自动批准 |
| 兼容 | 旧普通编辑继续使用现有语义；冲突字段不声明处置时仍冲突；未改变的人工来源从服务器上版继承，不能由客户端伪造 |
| WBS、依赖、负责人 | 本批归5.1返工，Codex实施核验；字段→审核→前端→帮助→回归→8798候选；唯一软件主线5.1→5.3，使用共享Planner，不自算关键路径 |
| 风险 | 证据丢失、并发覆盖、角色绕过、模型失败伪成功、帮助丢稿；用旧Revision/处置历史、事务409、现有角色门禁、可信计数、独立抽屉控制缓解；额外投入记R11 |
| 最小验证 | 一好一坏、全坏、人工补录、原文修正、再次保存、权限和冲突；帮助登录前/后、链接、Esc、焦点、编辑与录音状态；失败保留实际结果 |
| Acceptance | 定向/完整回归及CI通过；最终同一SHA三条真实路径、显示、持久化、隔离恢复后5.1才DONE，随后5.3连续五次；模型首次质量单独未通过 |

为什么这样拆：字段、处置、正文与帮助有独立状态所有者，可分别回退。替代方案见研究比较。最可能失败是旧错误证据继续污染补录或错误内容混入正文；先以隔离回放及API事务验证。完成需要可见按钮流程及最终发布证据，不能只凭单元测试。

ASSUMPTION A01：试用范围仍为中文发热/呼吸及匿名/合成材料；不增加诊疗、处方、训练或新疾病。
ASSUMPTION A02：帮助与应用同源，当前无禁止同源嵌入的响应头；浏览器Spike已通过，键盘和实际尺寸留产品回归。

Design Review PASS，允许已批准局部实现；不代表产品视觉、真实三路径、模型质量或发布Gate通过。
