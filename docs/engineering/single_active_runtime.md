# 8798单一活动环境维护说明

日常只运行8798使用测试版。8795展示版保留，切换前保存编辑、停止录音并退出页面；启动器还会核对后台任务及录音会话是否空闲。

## 配置与操作

在**已经登记、校验过的**活动环境`launcher.json`中显式设置：

```json
{"active_restart_policy": "unless-stopped"}
```

此字段只支持`no`和`unless-stopped`。旧双环境登记缺少字段时继续采用`no`，不静默改变其启动行为。启动器先核验另一版停止，再将另一版策略设置为`no`，最后设置活动版策略。两个环境不能同时自动恢复。Compose重新创建后须重新登记资源指纹、保留本字段，并执行启动器启动，不直接用旧容器ID。

通过桌面入口“启动服务／检查状态／切换到本版／停止服务”操作。维护命令如下，`--config`替换为本机登记文件：

```powershell
python -X utf8 scripts/doctor_pilot.py start --config "本机登记文件"
python -X utf8 scripts/doctor_pilot.py status --config "本机登记文件"
```

切换仍需要保存确认；端口占用或另一环境运行时不停止其他程序。活动容器异常退出或Docker恢复时由Docker策略恢复；明确手动停止后不会自动启动。不得以重启Docker代替模型质量验收。

## 就绪与故障

- `/health`检查网页进程；`/ready`另外核验真实模型、ASR、SQLite及目录。
- 成功推理缓存仍为300秒；应用每15秒检查，在剩余约60秒时尝试刷新，无需浏览器常驻。
- 每个模型最多一个探测；业务进行或排队时，探测延后。已经执行的探测不会被强行中断，随后业务优先取得推理槽。
- 摘要变化、未驻留、失联、刷新失败或缓存过期仍未就绪；不会保持过期绿灯或回退Mock。
- 此槽仅覆盖当前应用进程；部署须保持一个应用进程，不宣称协调其他应用的Ollama调用。

无法就绪时保留输入、查看运行状态及诊断证据。恢复旧镜像与登记配置不会覆盖业务数据库；数据库恢复是独立维护操作，不在普通启动时执行。

## 放行边界

本机制改善启动和就绪连续性，不修复病历抽取语义。模型首次输出质量、最终真实三路径、实际显示、隔离恢复与连续五次流程仍需独立通过。
