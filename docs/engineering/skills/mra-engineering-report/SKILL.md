# MRA 工程迭代汇报

先完成已授权的工作，再以本格式报告实际结果。此 Skill 只约束本项目的沟通与证据表达，不代替 PM、Research、Design 或安全推送规则，不授予采购、训练、合并或改动范围的额外权限。

## 固定结构

1. **目前的问题**：先说本轮解决了什么与仍失败的模块；区分本轮实测、历史证据和推断。
2. **解决方案与选择**：内部资产和必要的官方／成熟来源、候选比较、选择理由；未搜索时直接说明，不伪造来源或强做无关研究。
3. **当前阶段与下一阶段**：注明实时快照时间、WBS任务和Gate、唯一下一任务。读取失败时标注历史时间，不冒充实时；不把集成DONE等同模型临床质量通过。
4. **需要用户帮助**：仅列确实需要的输入或物理操作；没有则写“本轮不需要”。已有授权不重复征求。
5. **本轮交付与下一份输出**：给可操作入口、版本与证据链接；下一份交付应具体。失败格式为“模块／输入ID／预期与实际／影响／证据位置／下一最小验证”。
6. **工程师拆解**：按输入→ASR→角色→理解→校验→工作流→训练逐层归因，只列相关层；一次改变一个可验证因素。
7. **备注**（需要时）：范围、排期、返工或发布边界。

## 本项目必须保留的区别

- 模型首次输出、规则拦截、医生修改后结果分别统计。规则测试通过率不得写成模型准确率。
- 界面基线、模型候选与完整可恢复发布是不同交付。真实三路径及对应SHA恢复证据缺失时，不宣布稳定发布。
- 合成、历史回放、复用真实录音、本轮物理麦克风各自标识。假录音测试不替代物理证据。
- 知识指南是医生参考，不能自动变为患者事实；缺失、冲突、失败不可用固定文本／Mock／云端回退掩盖。
- 不承诺“所有病历均正确”。报告支持范围、具体失败和可拒绝路径。
- 遵循既有PM收尾：验证同轮快照→同步Obsidian→提交实质交付取得SHA→导出镜像→提交镜像→推送→更新PR。镜像repo_sha不指向镜像提交；纯只读无事实变化不制造提交。

用简洁中文，每项以结论开头。真实结果优先于测试数量或文档数量；没有完成的事项不写成已完成。
