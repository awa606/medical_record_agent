# 数据、模型与验证规模规划

这些数字是工程规划下限，不是统一注册样本要求。正式临床规模必须根据预期用途、终点、亚组和目标错误率做统计功效分析。

## ASR改进顺序

1. 记录设备、距离、噪声、削波、静音比例和SNR。
2. 生成16kHz单声道PCM规范副本，保留原文件和SHA。
3. 长录音用VAD、10–30秒分块、重叠、断句合并、标点和ITN。
4. 保存时间戳、speaker、role和原音频关系。
5. 热词和错误词典只作显式后处理，指标同时报告模型原始输出。
6. 按患者、说话人和原始会话隔离训练/验证/测试，再比较FunASR、SenseVoice等候选。
7. 只有错误稳定集中于领域词汇、口音或声学条件时才启动微调。

指标同时包含CER、医学实体召回、数值与单位完全正确率、否定词保留率、角色准确率、关键问答完整率、RTF、P95和峰值内存。FunASR训练格式和标签要求以官方说明为准：https://github.com/modelscope/FunASR/blob/main/docs/training.md

## 本地模型提升顺序

```text
固定DeepSeek在线比较基线
  -> 同一冻结病例输入本地Qwen
  -> JSON Schema + Pydantic
  -> 临床事实与原文证据核对
  -> 确定性候选方向/排版/安全门禁
  -> Before/After
  -> 达标后成为候选
```

本地化是Provider替换，不是转换DeepSeek权重。先用Schema、证据、RAG和规则解决错误；LoRA只在冻结集字段F1提升、危险语义错误保持0且数据隔离合格后评估。Ollama结构化输出参考：https://docs.ollama.com/capabilities/structured-outputs

## 数据下限

| 目标 | 建议起步数据 | 仅能证明 |
|---|---:|---|
| Alpha链路Smoke | 20–60个合成或课程病例 | 接口和明显逻辑错误 |
| ASR冻结评测 | 10–20小时、≥30名说话人 | 初步比较质量、角色与时延 |
| ASR微调候选 | 50–100小时人工转写、≥50名说话人 | 领域适配候选是否改善 |
| 语义安全集 | 200–300组对照语句 | 否定、主体、时间、数值工程回归 |
| 字段抽取候选 | 300–500例医生复核会话 | 第一个候选版本的训练/选择 |
| 知识检索 | 200–500条双人复核查询 | Recall@5与引用完整性 |
| 单病种病例检索试点 | ≥1,000例授权去标识病例 | 有限场景相似性评估 |
| 科室级静默试点 | ≥1,000次真实就诊、多名医生 | 工作流、泛化和失败模式 |

60–100例Beta数据只属于课程工程验收。若独立冻结集观察到0个严重错误，“3/n”近似下，300例对应95%上界约1%，3,000例才约0.1%；仍需结合真实终点、亚组和统计计划解释。

## 数据分层与禁用项

- 训练、验证、最终测试严格独立，按患者、说话人和原始会话分组。
- Toyhom和网络问答只用于语言压力测试，不作为临床真值或治疗监督标签。
- 原始音频、身份数据、医院病例、数据库和模型权重不提交Git。
- 未获医院授权前，相似病例Gate、治疗CDS Gate和Enterprise Release Gate均保持BLOCKED。
