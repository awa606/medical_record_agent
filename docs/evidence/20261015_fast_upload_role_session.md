# 快速上传的身份确认恢复（2026-10-15）

## 复现与原因

在 `a5a373fc` 离线恢复环境，E-15 通过可见按钮上传已有授权 60 秒音频，FunASR 返回 21 段转写。主状态要求确认两位说话人，详情却显示“只读”，无法保存角色。

原因：快速分支使用旧 `/api/audio/upload` 与 `/transcribe`，没有创建 ASR 会话；身份修改必须通过现有会话 PATCH 保存。测试先复现快速路径缺少保存按钮，失败记录保存在本地 `upload-role-red.txt`。

## 最小设计与决定

- Research：PASS。现有 `/api/asr/sessions` 已支持 `recognition_mode=fast/follow`，无需新增接口或依赖。
- 增量设计：PASS。两模式共用已有会话上传和事件恢复流程，保留选择的识别模式；仅删除前端旧快速分支。角色 PATCH、生成前 409 门禁和历史引用逻辑不变。
- 不调整模型、公共 API、数据库结构、阈值或三栏布局。旧批量接口继续兼容其他客户端。
- 回退：还原本次前端提交。已知旧快速路径会阻断身份确认，不能将其标为完整流程通过。

新增按钮级回归，从登记、开始接诊、选择模式、上传到身份确认保存，使用隔离数据库与 Mock ASR（不作为真实语音质量证据）。快速和跟随模式均创建持久会话；真实本地 PATCH 返回200和角色通过。另复用现有409阻断恢复测试。
