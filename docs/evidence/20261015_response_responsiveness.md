# 转写期间并发响应：脱敏阻塞定位与修复

## 目标与范围

Alpha 5.1 VERIFY。本批处理“转写时登录、历史查询受到拖累”的确定性并发缺陷，不改变模型、临床校验、数据库、公共API或三栏布局。医院临床有效性、物理录音、实际缩放和5.3连续五次仍需独立验收。

开发基线 `dfd2df0`；运行基线 `920c3c9`（后端为 `770bd920`）。发布只从运行基线选取本批修复，不携带开发分支上未放行的模型实验。

## Research：PASS / ADAPT

**问题**：ASR本身已在同步后台任务线程中运行；最终响应脱敏却直接在ASGI事件循环调用SQLite。每个字符串会读取身份映射，JSON及SSE均受影响。10月13日真实转写期间发生过20秒登录超时；本批尚不将该历史超时全部归因于脱敏。

| 候选 | 适配与代价 | 结论 |
|---|---|---|
| 现有Starlette线程池 | 已有依赖，复用AnyIO有界工作线程；保持逐响应/逐帧顺序。BSD-3-Clause；离线可用 | 选择，只迁移阻塞调用位置 |
| asyncio.to_thread | Python标准库，另用默认执行器；不复用应用已有线程预算 | 不采用，缺少额外执行器的必要性 |
| 批量缓存身份映射/异步数据库 | 可能减少查询数量，但涉及身份映射一致性、失效及更大改动 | 留作后续有测量依据的优化 |

U01：线程池是否解除事件循环阻塞、同时保留脱敏及摘要？隔离Spike只修改调用位置，在匿名化过程注入350ms同步等待，向同一ASGI应用发起独立健康请求。JSON基线413.21ms、候选32.44ms；SSE基线380.39ms、候选29.84ms。候选均低于预先150ms阈值，电话被脱敏，64位版本摘要未改变。这是工程调度实验，**不是实际ASR延迟成绩**。原始记录在本地 `.artifacts/asr-responsiveness-20261015/privacy-spike.json`。

已保留完整中间件红测试：JSON、SSE完整帧、SSE末尾帧三项均失败；非法JSON的两项失败保护通过。由慢脱敏期间能否完成另一请求验证行为，不依赖某台电脑的绝对性能。

官方方案已解决阻塞I/O的调度问题，可直接复用；最大风险是共享线程池饱和，不能由本次测试推出任意并发容量。回退只恢复上一镜像，无数据库迁移。停止扩大研究，进入局部实现与真实音频测量。

## 增量设计评审：PASS（局部缺陷）

- **交付/PBS**：响应中间件修复、并发与失败保护回归、真实转写并发记录、可回退候选。
- **输入/输出**：应用JSON字节或SSE帧 → 相同脱敏策略输出；完整JSON只处理一次，SSE逐帧等待处理完成后发送。错误响应不包含原始正文。
- **职责/接口**：中间件负责响应隐私；现有`anonymize_payload`和`anonymous_sse_frame`内容规则不变。线程内创建并关闭各自SQLite连接，不跨线程共享连接。
- **Assumption A01**：10月13日的20秒超时可能还有CPU、网关或日志因素；用真实60秒授权录音及并行健康/登录/历史读取复核，未复现不推定全部解决。
- **WBS/依赖**：归属5.1缺陷修正；完整发布后才5.3。16项、99h和日期不变；额外投入记R11。不重算关键路径；使用同轮Planner快照。
- **风险/回退**：共享线程池可能排队；日志和事件文件读取尚未迁移。若真实负载仍超时，记录最慢层，保留旧运行版本，不增加线程数掩盖原因。
- **验收**：JSON、分块SSE及尾帧不阻塞独立请求；非法JSON安全失败；电话脱敏与版本摘要不退化；真实ASR期间并发读有记录且无超时；完整回归与候选检查通过。

这样拆分可先修已证明的调度缺陷，再判断真实负载；无需更换ASR或数据库。最可能失败在资源竞争或其他同步I/O。最小验证为既有中间件+慢I/O+独立请求；完成证据须包含修复后测试及真实运行数据，不能仅靠代码审查。
