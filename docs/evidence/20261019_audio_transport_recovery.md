# 2026-10-19 音频生成中断与错误恢复修复

## 本轮实际失败

18019候选 `9af10d7` 的E-15使用既有授权60秒音频；用户手动选择文件并提交。实际会话记录为跟随播放模式，63.1822秒完成21段转写；这不是“尽快识别”延迟验收。工程操作者在页面确认A为患者、B为医生，未重复上传或执行ASR。

保存角色后自动建立task11。首次字段提取连接DeepSeek时发生 `URLError`，没有取得病历字段；原音频、21段转写及人工角色确认仍保存。旧诊断只保留异常类名，无法确定首次错误究竟来自DNS、TLS还是连接阶段。随后一次无凭据探测得到HTTPS 401，另一次TLS探测超时，只能证明连接存在波动，不能反推原始根因。

同时定位两处确定性界面缺陷：

- 任意音频任务失败都显示“智能转写失败”，实际执行步骤已明确为 `FIELD_EXTRACTION`。
- 角色保存先排队临时preview，再触发正式任务；preview未与正式任务互斥。正式请求失败约10秒后，临时preview产生第二次独立调用。这不是Generator自动重试，但同样违反单次显式操作不隐式重复推理的要求。

两次失败均保留预算预留；未重置账本、放宽门禁或回退Mock。修复前累计6条调用记录，保守计入0.225574元（含失败预留，并非服务商实收账单），预算仍为20元。

## 局部修复

1. 根据正式任务步骤区分字段提取、草稿生成、安全校验及真实ASR失败。已有转写的生成失败显示“病历生成中断”，明确保留原文；唯一主恢复动作复用已有“重新生成病历”，不重做ASR。
2. 正式生成开始前取消待发preview，发送端再次检查正式任务和生成意图；失败、历史恢复均不自动补调preview。只有显式新输入才恢复预览。已经发出的云端请求不能保证被客户端取消，因此重点是发送前阻止。
3. 在线适配器只保存固定传输分类（DNS、TLS、证书、超时、拒绝、重置、网络不可达、未知）。不保存异常任意正文或URL，不改变TLS校验、请求参数、重试次数和失败费用预留。
4. 手册补充按具体失败阶段恢复的说明。

公共业务接口、数据库、七字段、模型、提示词及采样参数不变。原失败记录不改为成功；修复后的手动重试属于新的验证结果，不能覆盖首次失败。

## 恢复按钮的绑定限制补修

独立代码审阅进一步发现：原“重新生成病历”仍调用既有生成接口，但接口对已经绑定任何任务的就诊均返回409，失败后也无法恢复。新增回归先复现该409。

最小修复沿用原接口：只有原任务FAILED、归属和就诊一致、就诊仍开放，且整个就诊没有病历版本、审核或导出记录时，显式生成请求可以创建新任务并替换当前任务指针。绑定检查与替换使用同一SQLite写事务；第二个并发请求不得同时接管。旧任务、步骤和错误结果不改写，新任务审计记录关联原失败任务。默认绑定接口仍禁止替换，只有两条明确生成路由启用此窄化恢复分支。

已存在病历、审核、导出、活动任务或归属不符仍拒绝；绑定失败的新任务标FAILED，不留无主运行任务。未增加公共接口或数据库字段。9项新增恢复检查及既有隔离、费用测试共37项通过；全量与真实页面恢复继续单独验收。
