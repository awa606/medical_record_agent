## 2. 内存阻断的同步定位与处理

此前4.67GiB、恢复后的5.27GiB属于不同时刻，不能推导“停服务增加占用”或内存泄漏。本轮在同一个已授权窗口，先确认无活动任务和未保存编辑，使用容器内SQLite Backup API及`closing()`备份，再暂停登记中的8798应用、网关和旧2666，核对精确容器ID与进程退出。

Windows同时读取GlobalMemoryStatusEx和CIM，取较小值判断，未降低原8GiB启动线或4500MiB显存线；准备在15／45／90秒观察，达到条件且稳定复核通过即停止等待。本机BusyBox不支持GNU `ps --sort`，执行前已改为其实际支持的进程元数据采样，避免管道掩盖错误。

| 采样点 | Windows可用内存 | 判断 |
| --- | ---: | --- |
| 暂停前 | 约6.46GiB | 未达启动线 |
| 容器进程刚退出 | 双读数较小值约6.97GiB | 仍未启动模型 |
| 暂停后15秒 | 双读数较小值约9.08GiB | 首次通过 |
| 稳定复核 | 双读数较小值约8.91GiB | 通过后才启动固定协议 |
| 包装器正式预检 | CIM约9.34GiB、显存5533MiB | 原守卫通过 |

WSL匿名页由9,284,612KiB降至约322,216KiB，原两大Python进程均消失；Windows侧回收并非与容器停止瞬间同步。本次证据支持“确认进程退出并等待实际回收”能解除当前阻断，不能倒推所有历史采样原因。没有重启WSL、清理全局缓存、关闭无关应用或修改`.wslconfig`。

资源包装器只控制本次新建Ollama及其子进程；预热5.765秒，运行采样未触发原低资源停止线。结束后模型返回`unload`，隔离11435监听关闭，然后恢复原服务。采样不是精确峰值，不宣称模型绝对最低内存要求。

## 3. 模型首次输出、映射与校验分别判定

固定输入为合成治疗事实“吃了布洛芬以后体温降下来了”，原句、事实ID、目录、主体和语义定义均未改。实验变量为输出表示及对应格式说明：七字段ID数组，与按事实ID组织的独立布尔判断。后者允许所有true／false组合，没有强制true、自动填充或失败重试。

共6次病例请求、1次空预热、零自动重试。离线评分禁网、模型调用0，原始响应SHA前后未变。该阶段使用映射器与`ground_fields`，没有将它冒称为完整Generator、完整病历召回或临床质量通过。

这是一项有对照的固定正例改善；不能据此确认模型会正确输出false、处理自我纠正、拒绝家属自身事实，或覆盖所有病历。不得把目录硬过滤后的安全拒绝计为模型理解能力。

## 4. 晋级前检查与下一最小验证

扩大模型调用前，先检查既有开发材料是否能在当前目录和完整Generator中表达正确结果。显式正确选择仅用于离线可表达性测试，标为ORACLE_PREFLIGHT，不是模型首次成绩，也不自动补到模型输出中。

原开发例027提供真正的false控制：“刚才说发烧，其实没有发热。”既有标签要求主诉缺失、现病史保留否定。当前目录第一句仍允许主诉，因此模型必须明确拒绝这一已撤回主诉；第二句现病史必须true。第一句是否保留在现病史中预先允许两种写法，不根据结果改标签。原标签字面“否认发热”与原句“其实没有发热”的差异单独保留，不要求ID映射器改写原文来凑通过。

### 4.1 反例预检与首次模型结果

先禁网执行两种显式正确选择：主诉均为空；现病史仅保留后句时为complete，同时保留自我纠正叙述时为partial。两种语义均可表达、完整Generator均有结果；但两者均不满足原标签字面“否认发热”。该字面差异保留FAIL，没有改标签或改写原文，预检不计入模型成绩。

反例另行预注册协议`5e8ae5addf53cd614d698ef4eeac34c6913e8280d948ff19faac66d7ef3d9351`：沿用正例的模型、参数、语义前缀和自由布尔表示，仅换为原开发例027及其目录。八种true／false组合都合法，没有强制false或true；计划最多3次，首错即停。

实际第一次响应1.359秒，正常结束、Schema合法，却三个值全部true：主诉选择了“刚才说发烧”，现病史同时选择两句。主诉判断与冻结预期矛盾，`REJECTED_FALSE_CONTROL_FAILED`；只调用1次，没有继续第二、三次，也未扩展21次压力测试或调整提示词。本例证明本候选仍有语义混放问题，不能因固定正例3/3就部署。

### 4.2 完整生成链发现的确定性保护漏拦

将这份实际坏选择通过既有映射器及完整Generator禁网回放，修复前主诉仍为complete，`wrong_chief_accepted=true`。正文与所选引文逐字一致，仍不能代表它符合完整原文的最终陈述；这里是撤回语义及校验链问题，不是解析失败，也不是映射器把正确选择丢掉。

本轮据此建立完整生成链失败回归，并局部修复明确自我纠正的主诉保护。只处理同一句、明确单一患者、无其他主体和明确临床时态的撤回关系；出现明确历史发生／退热或他人线索时，本新增保护不猜测关系，原有其它校验照常执行。复用现有症状别名，发烧／发热、头疼／头痛等不因用词不同漏掉已验证的撤回关系。不改原文、字段正文、引文、编号、模型、参数或公共结构。

完整生成链原缺陷先8项失败；独立审查又找出时间与后置主体的误拦，分别先6项、1项失败，随后收窄范围。最终`tests/test_self_correction_grounding.py`为28通过、0.50秒。相邻引用、家属引用及医生补录三份测试此前42通过；它们发生在最后收窄前，保留阶段说明，最终CI另行覆盖，不将旧通过冒充最终源码全量通过。

实际A4坏选择在冻结源码下禁网回放，主诉从complete变为conflicting，原因明确为原文已撤回；原value、引文、index和fact_ids不改，其余六字段及候选诊断与修复前逐字段相同，现病史仍partial而不是被丢弃。仅勾选医生确认不能绕过原安全门禁。这是规则保护改善，模型首次错误仍FAIL。

本新增保护不修复原有“先否定、后重新阳性”的跨子句误拦；该失败单独保留，没有把一个新helper未触发当成完整正例成功。8798仍保持原运行后端，本次保护是已回归的源码候选，研究契约未部署。Research仍为`NEEDS MORE EVIDENCE`，没有修改正式Gate或启动验证／冻结集的大规模调用。
