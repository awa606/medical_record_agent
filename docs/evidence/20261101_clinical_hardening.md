# 2026-11-01 临床化硬化：页面布局、就诊类型与安全校验

## 页面布局

- 新建 `doctor-visual-v3.css`，统一顶栏、患者横幅、导航、步骤条、三栏卡片、分区头、状态胶囊、表单与按钮。
- 就诊工作区：深青蓝患者横幅、白色选中导航卡、蓝色步骤胶囊、左侧强调条的病历分区。
- 工作台：任务面板改为内容高度，避免只剩一条任务时出现整屏空白。
- 管理后台：修复选中项悬停时深色文字落在深色背景的问题。
- 登录、工作台、就诊、管理、index、debug、帮助首页/子页、320/375/720/1024/1280/1440/1920 全部重新巡检。
- index/debug 去除“课程/期末/评分”措辞，改为临床试点候选与内部开发页。

## 后端临床化

1. **就诊类型**：新增 `visit_type`，医生可填初诊/复诊/留观；PDF 标题和页头“就诊类型”随之变化。
2. **ICD-10 格式校验**：
   - 新增 `app/services/clinical_codes.py`；
   - 校验 `^[A-Z][0-9]{2}(\.[0-9A-Z]{1,4})?$`；
   - 格式错误会进入导出阻断错误；未知但格式正确的编码仍允许，避免锁死医院自有编码库。
3. **过敏-处理冲突**：
   - 新增 `allergy_treatment_errors()`；
   - 识别青霉素/阿莫西林、头孢、磺胺、阿司匹林等明显冲突；
   - 支持“否认过敏”“避免使用”等否定/规避语境；
   - 冲突进入导出阻断，要求医生修改处理意见。

剩余临床缺口：
- 患者主数据尚未与 HIS/EMR 对接，患者字段仍为病历内手工录入；
- ICD-10 只有格式与少量常见编码提示，没有完整授权编码库；
- 无 CA 电子签名；
- 过敏冲突是文本级提示，不是药品知识库/处方审核；
- 复诊/留观目前只换标题与字段，没有独立模板和既往就诊自动带入。
