## 重新签署和并发写入

**最终 R3 与并发签署。** 在同一候选病例上移除 R2 的编码、保存 R3，页面显示旧批准失效并禁用导出；再次逐项签署后，下载文件名为 `task_1_R3_export_3_medical_record.pdf`。重新读取原 R2 文件仍有 R50.9；R3 没有此编码，两份 PDF 的布洛芬与过敏事实均在。实际病例页、批准、文件三个环节一致。

隔离接口另复现过两种旧实现竞争：正文相同但版本已换时可能签错版本；签署后另一窗口保存，新版本可能被旧请求重新标成已批准。新实现同时检查版本 ID 和内容哈希，将批准、分项、任务状态和审计作为同一次事务写入。强制末尾审计失败时全部回滚；历史凭证仍保留。相关 53 项通过。

## 展示前界面巡检

[首次远端运行](https://github.com/awa606/medical_record_agent/actions/runs/41408976421)的完整 Python 回归通过，后续独立界面巡检失败。复现发现，320px 窗口的版本徽标导致横向多出 20px，滚动编辑时章节按钮与输入框相交；巡检还在寻找旧的章节标题。候选现在把导航放在滚动区之外，基本资料仍可一次展开，小窗口的版本标识在可用宽度内换行。校验脚本检查四个临床章节及基本资料，保留对比度、点击遮挡和无障碍检查。同一巡检在本机 79 项通过，相关页面和诊断编码回归 18 项通过。此项没有改变生成、审核、数据库或旧展示端。

[第二次远端运行](https://github.com/awa606/medical_record_agent/actions/runs/41414364179)另发现丢失本地追加内容的时序问题：1,699 项通过、1 项失败、4 项跳过。服务器已保存第一版，但读取状态失败后，后台步骤请求正好返回并替换正在获焦的输入框。迟到的同任务刷新也可能用服务器字段覆盖医生正在改的文字。修复保留活动编辑器与独立草稿，以服务器已接受的那次保存为比较基准。人工控制后台返回时刻，分别尝试追加及清空；读取最新版本后能找回本地修改，服务器仍是第一次保存的文本，只有一次保存请求。相关编辑、编码、历史读取与章节导航 24 项通过；与以上数字存在重叠。
