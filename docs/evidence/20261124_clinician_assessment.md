# 门诊病历中的本次医生评估

当同一份门诊记录有医生本人的意见和系统产生的候选时，经治医生可以在已生成的病历上单独录入本次评估。打开病历的“诊断处理”，点击“编辑本次医生评估”，填写自己的原文，选择“医生记录”或“待排”，保存后按既有分项审核流程签署。普通字段的修订、医生评估、系统候选及其来源均可在各自的版本中回查。“医生记录”保留录入者的措辞，系统没有据此判定确诊。

## 版本与签署

服务端按登录的经治医生和保存时间标注来源。工作台可在支持手录的服务上编辑该项。旧客户端省略该项时沿用已存内容，明确清除时保存新的修订。评估内容、记录状态、作者及时间均进入该版内容摘要。签署后如有编辑，新修订须重新审核。PDF 分别列示医生原文及状态、记录人和时间，以及系统候选诊断。仅有转述、未由医生作出判断时可留空。

独立工程复核使用隔离的模拟账号、合成就诊和实际签署件。从上一维护实质版本 `de4777b` 生成并签署 R2，升级后原修订号、内容摘要和取回的原 PDF 一致。经治医生写入获准，另一位普通医生收到 403。旧客户端省略字段时原作者和时间保留，显式清除后新稿没有该栏。签署的“待排”样张按原状态打印。

历史导出文件仍归属其产生时的修订和批准。进入下一待签版本后，当前下载接口返回 409。新版本签署后，在当前批准下用旧摘要请求返回 404。旧字节仍保存在原导出位置。院方对历史签署原件的调阅角色、保存期限、补打方式和回退安排需另行核定。

在最初没有降版保护的隔离库中，带手录的 R3 签署后换回旧程序。按原 SHA-256 取回时字节一致；旧程序重新导出同一修订返回 200，缺失医生手录。再在旧程序中只改另一个栏位并签署，草稿和 PDF 也漏掉了手录。回退试验保留了原件和错误重打件。

现有数据库按就诊保存最低写入协议。从已有修订迁移时，即使当前栏已被医生清空，早期手录仍能识别。真正的旧服务在两组受保护病例上共尝试十次修改、批准或重打，均被阻止，修订、批准、分项、审计和 PDF 字节保持原样。三个未曾手录的对照共九次普通操作均成功。在实际旧服务上，受阻时显示通用服务错误。降版后应使用已签原件的摘要取回原件，并切回支持手录的程序后再书写或签发。正式院内部署的停机切换与恢复仍需按院方环境演练。

## 页面与纸面

在普通模拟医生的工作台，已实测本人署名、待排、留空、并发冲突、手动恢复及旧版本对照。旧服务意外接受却没有存入评估时，新页面保留医生原文并提示重新核验。原窄屏顶部步骤文字在 390 像素下越出单项最多约 19 像素。调整后，390 像素可同时显示五个步骤，360 像素可通过键盘横向查看完整五步并继续移出焦点，1366 像素沿用原布局。

原两份短手录样张的第二页只有签名行和提示。调整有手录记录的留白及分页后，新生成的两份短样张在一页内保留医生原话、记录来源、治疗栏和签名，长样张跨两页并保留 180 次测试短句。每页标有就诊号、页码。上述结果来自实际 PDF 渲染。实体打印和院方模板尚待现场核验。

## 模型首次主诉与人工录入分别评估

十次真实本地 Qwen3:4b 首答来自十个新合成文本。冻结首答后分别交给原处理和一项转述规则候选。两组均生成 9/10 份待审首稿，均有 8/10 满足试前主诉判据。需要保留本人主要症状的五例中，两组均保留四例。十次对照中字段、正文、安全检查、错误和终态逐项一致，该候选未进入应用。

一例把舅舅的头晕写为患者主诉，患者本人的手腕疼只在现病史出现，安全检查通过。另一例有医生的“待排”原话却未生成首稿。手录需要已有可修订的病历。首稿未生成时如何转入人工起草仍待处理。候选诊断也可能由既有规则补入，单科室纯文书试点须确认是否允许显示这类输出。

隔离的演示生成器还把“本次我写的判断是过敏性结膜炎”填入过敏史，并可随人工批量审核进入纸面。上一维护版本和本次手录版的 R1 均可复现，发生在医生开始手录之前。该输入尚无来自真实模型或临床人员的等价验收结论。

真实中文门诊原音与同次病历的获权配对、目标科室医生回卷、院内签署及回写和学校正式评分各自登记。此处的测试账号与合成材料用于工程复验。
