# 回执迟到时保存医生正在编辑的版本

同一普通测试医生在两个独立浏览器窗口打开一份合成 R2。甲修改主诉，乙修改过敏史并先保存 R3。旧维护版在导出资格回执暂时失败、或迟到的回执已经来自 R3 时，允许甲用眼前的 R2 字段和 R3 的版本号保存。请求返回 200，形成 R4，乙刚补录的过敏史在新稿中退回旧值。原 R3 仍留在历史里。这里测试的是普通编辑保存，与签发药敏专栏的隔离试验分别核对。

## 真实浏览器比较

| 甲的回执状态 | 旧版第一次点击保存 | 修订后第一次点击保存 |
| --- | --- | --- |
| 通常已取得 R2 | 409，保留甲草稿与乙 R3 | 409，保留二者 |
| 首次回执返回 503，随后恢复 | 200，错误覆盖乙的字段 | 409，保留二者 |
| 延迟返回的内容仍是 R2 | 409，保留二者 | 409，保留二者 |
| 延迟请求返回时已是 R3 | 200，错误覆盖乙的字段 | 409，保留二者 |
| 首次回执 503，但另一窗口没有修改 | 200，正常新建 R3 | 200，正常新建 R3 |

每组使用独立临时库和合成就诊。修订后，四组冲突均验证了甲仍可通过普通按钮加载最新、重新应用自己的修改、再次保存。新 R4 中同时保留甲的主诉和乙的过敏史。复验未签发临床记录。实际两个终端是同一台电脑中的两个普通浏览器会话。

## 修补范围

编辑开始时留存当时所读病历的任务、修订号和内容摘要。保存期间如需补取缺失的摘要，只使用该任务、该修订的回执。版本已变化时进入原有冲突处理，保留本地内容。已读历史、取消或切换就诊的状态不用于确认别的版本。服务端沿用原来保存事务中的版本与摘要核验。

仓内的浏览器用例保留原有旧版冲突场景，同时覆盖回执暂时不可用、已返回新版本两种之前漏掉的情况，并核对重开与恢复过程。

另用普通医生检查旧格式。仅有原修订号且缺摘要时，同版仍能保存，异版在提交前提示冲突并保留本地修改。完全缺少修订号时，编辑器提示重新打开就诊；恢复正常读取后可保存。两次暂扣回执期间，取消和切换入口禁用，回执到达后可操作。另一个验证者复查了两人修改同一栏的情况，“重新应用本地修改”只把值带回编辑框，再次点击“保存”才会生成新版本。冲突恢复区目前只列本地曾修改的文字，同栏不同版本尚未在同一处并排显示。
