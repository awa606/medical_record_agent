# 模型未出稿时由经治医生起草病历

在已接诊、首次生成已经失败、尚无修订或批准的就诊，普通经治医生可从工作台选择“手写病历”，填写主诉或现病史。首次保存得到待逐项审核的 R1。系统记录执笔账号、时间、原失败任务及失败分类。随后修订、软件审核与导出沿用病历原有流程。手录的症状没有自动音频引文，也不会自动生成候选诊断。

## 可复查的工程证据

| 场景 | 实测结果与范围 |
| --- | --- |
| 原流程与人工接续 | 两份虚构门诊输入各使用已保存的模型首次回复，复现维护版零修订的失败。旧版可重试生成，失败后仍没有病历。当前人工接续另存 R1，原失败任务内容保留。 |
| 内容与权限 | 来诊原因可单独成稿，也可只填现病史。空白请求、非经治医生、已存在模型首稿的病例均有独立对照。未经核对的说话人无法直接成为手录的引文。 |
| 断线和多人操作 | 浏览器丢失已经提交的回执，原内容和 UUID 重送得到同一任务和修订。两个不同请求竞争同一就诊时，仅一个能写入。数据库在登记去重回执或审计前中断时，整次事务回滚，再用原请求可正常保存。 |
| 用户页面 | 合成账号从正常医生工作台操作，桌面与 390 像素窄屏均可填写。编辑内容按当前标签、账号、就诊及失败任务恢复。已提交、已处理或已退出的情况各自核对，可从已存版本重读来源。 |
| 审核与签署件 | 手录病例的 R1、R2、R3 均有逐版软件审核和实际 PDF。纸面标明首稿来源、经治医生、实际软件审核人的留痕及签名填写处。演练中的签署为软件流程，医院电子签章留待院内核验。 |
| 实际旧程序 | 旧写协议 1 和 2 都能读取当前已签原件。旧程序对已受保护的人工首稿修改、首次批准或补打时会报通用 500，原件和账本保持完整。两个旧程序各自仍能完成一份普通病历的修订和签发。回到新版可继续修订并签发。 |

**仍需处理的实际限制。** 一旦同一任务后续版本生效，按现有任务下载入口请求上一版本 PDF 的摘要会得到 404。当前批准件和已下载原文件的摘要均可核对。院内历史病历调阅、留存和凭证恢复须按医院规定另行落实。上述合成操作没有形成目标科室的医生评审、真实病历授权或医院放行。
