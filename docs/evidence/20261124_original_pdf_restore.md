## 医生在缺件时看到什么

修补前，医生重开历史就诊会看到“本版本 PDF 已导出，可再次下载”。即使文件已缺失，应用仍能查到当初导出的回执。普通历史下载请求（附原 SHA-256）此时返回 404。运维从同次冷备放回原件后，医生点重试即可下载。后台的导出资格表示当前签署版本允许导出，与原件是否存放在输出目录分别核验。

修补后，初次打开显示已有 PDF 导出记录。原件无法读取时，界面说明如何恢复同次备份的原件并重试，也告知重新生成会产生新的导出记录。该问题只涉及医生界面的文字，下载、文件摘要校验、审核与导出资格使用原有流程。

另建一次有独立文件摘要的对照，旧版和新版分别使用同一冷备、同一普通医生、同一浏览器和服务地址。两个版本均先返回 404，补回原件后通过重试下载相同 PDF（SHA-256 `aecf41d08259d06e60767f03d5f6f0be344ffa5736a64f924dca9cfdda468586`）。两个版本都保留 3 份修订、1 条签署、1 条导出回执，未调用生成导出件的接口。浏览器实际收到新版本的脚本，界面和相关服务专项共 53 项通过。

本次使用工程账号和单个合成就诊。医院侧的身份接入、密钥恢复、语音与附件、异地介质、恢复时间目标和数据恢复点目标都需要在院方真实环境中核验。
