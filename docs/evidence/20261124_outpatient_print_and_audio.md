# 门诊病历首页补打、候选诊断与原音恢复

普通医生测试账号在临时库中接诊合成患者、保存 R2、逐项审核、签署并下载 PDF。为复现历史就诊，测试在隔离库中预置明确的历史就诊时间。每个就诊从原导出回执取文件两次，下载内容与磁盘原件按 SHA-256 核对。

旧维护提交为 `7fb47f7`。最终导出器 SHA-256 为 `bfe12627343c06c76c7e290dfb7b07c649176baf56722830f58b61e7d9cf847d`。五例旧版均未匹配，最终版五例全部匹配，最终版十次下载均返回 200。补打按就诊日期计算，对显式时区沿用病历页面的 UTC+08:00。未注明时区的历史记录沿用原墙钟日期，实际就诊日期缺失或冲突时，首页年龄留空。已存原 PDF 依原回执读取，新的渲染只影响新生成的导出件。

工作台只有通用过敏史。旧版会把花粉或花生过敏直接印进“药物过敏史”。新生成的首页使用“药物或其他过敏史”，逐字保留该栏内容，并按已保存的审核状态区分未询问和接受缺失。没有独立药敏记录时，未据此生成阳性或阴性药物清单。《病历书写基本规范》第十二条列有首页药物过敏史。2024 年《门（急）诊诊疗信息页质量管理规定（试行）》第六条覆盖药物或其他过敏史，第十条对病历书写另有要求。进入真实院内病历前仍需科室和病案部门确认专栏采集、复核及接口映射。[病历书写基本规范](https://www.nhc.gov.cn/wjw/gfxwj/201002/79d42b9c8b3f47ee91000d31de116784.shtml) · [门（急）诊诊疗信息页质量管理规定](https://app.www.gov.cn/govdata/gov/202409/10/519291/article.html)

两版本各签署十个预先固定的合成就诊，已签的通用过敏字段逐项相同。最终版十份 PDF 的标签均与原字段范围一致，九份非空原文全部保留。另有一份只记录“未询问”，打印时保留了医生确认的未采集状态。未据食物或花粉史推断药物反应。每份都有独立签署和导出回执。

## 候选诊断的触发依据

“自测 36.6 度、因咳嗽就诊”在两份已保存的真实本地模型首答中都没有候选，维护版的规则随后加入了两条。固定两种提示各六份首答，保持模型原输出不变，只在隔离副本改变规则和相邻字段路由。两份出错首答的两个额外候选均被移除。独立评估者另行冻结 24 个中文合成就诊和判分方法，再通过普通医生入口逐个生成 R1。这里的独立验证使用项目的模拟字段提供方，十二份历史首答的回放也没有重新调用模型。

| 两种候选及其来源 | 维护版 | 研究候选 |
| --- | ---: | ---: |
| 两个对象有无、状态及必要引文都正确 | 17/24 | 18/24 |
| 上述条件满足，且未夹入已标明的无关原话 | 15/24 | 16/24 |
| 缺少依据时仍误发“发热待查” | 5/12 | 4/12 |
| 缺少依据时仍误发“肺部感染待排” | 4/18 | 3/18 |

“发热待查”的阳性召回均为 12/12，“肺部感染待排”均为 5/6。亲属、测量对象和过往症状在部分病例中仍混入判断。仓内原有 60 例也仍有一例多发候选。保留原失败及研究版本，不在维护版启用这项候选策略。这里没有临床诊断正确率或真实患者结局。

## 从新目录找回原音

在断网 Linux 容器中用一次本地 FunASR 处理全新的中文合成录音，停服后按同次备份在 Windows 新目录恢复。仅恢复 SQLite 时，ASR 会话与媒体读取返回 404。再还原上传目录六个文件后，同一普通医生重开原就诊，浏览器播放器开始播放，文件读取为 200，分段读取为 206。源文件和目标浏览器读取的 323,158 字节逐字节一致，SHA-256 为 `e402cf5dff85f0ec1185b3584cd23371ed69c76444adc61baa4517ba7f822470`。六个读入口在未登录时均为 401，另一普通医生均为 403。工程检查在静音自动浏览器运行，人耳听辨、真实数据、异地恢复和医院核定的恢复时限另验。
