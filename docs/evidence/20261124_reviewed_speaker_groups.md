# 三人合成初诊的身份复核与课堂试用

右腕就诊的跟随转写把父亲和医生连续说的话合成了一个 9.02 秒的音段。医生后来逐段写入患者、陪同人员、医生三个身份。旧工作台把整组建议预填成待保存值，保存后仍可将互相矛盾的身份判为通过并创建草稿。普通模拟医生在真实页面复现了这一过程。[原始音轨与首次观察](20261124_portable_session_review.md)

## 重新核对旧记录和新修改

服务现在保留逐段人工身份。遇到组内矛盾时，页面列出对应的音段、时间和回听按钮，整组选项不允许覆盖这些记录。只有主动选定的相容组才会提交。历史音频和已有会话在读回及生成前均重新检查。界面对话框的“保存”与服务器独立检查使用同一组正、反例验证。

| 普通医生操作与输入 | 实际结果 |
| --- | --- |
| 已逐段核对的矛盾组，直接保存或试图改整组 | 两条真实页面路径都无角色 PATCH，原先的三个身份均可重读。生成返回 409。 |
| 逐段保存患者、陪同人员、医生 | 三次保存均返回 200。三次检查均阻止生成。只订正原话也可单独保存。 |
| 打开旧工作台曾保存为通过的矛盾记录 | 会话与音频转写均显示需要复核。请求生成返回 409，原因为 `manual_segment_role_conflict`，没有创建任务。 |
| 三个声音组与已知四段正确对应 | 普通医生明确选择后可生成。属于医生的两段仍同属医生。此例用已知分轨制成，未重跑声学模型。 |
| 混合录音此前没有逐段标注，直接明确将后两段设为陪同人员 | 仍然可以生成任务。最后一段实际来自医生。声学错分和未被发现的整组误指仍妨碍临床使用。 |

## 键盘从帮助回到正在编辑的病历

远端第 45379990407 次 CI 有两项内嵌帮助用例失败，另有 2,011 项 Python 测试通过。旧版按 Escape 关闭帮助 iframe 时触发一次额外的会话重新核对，焦点落到了页面主体。修复后，医生从帮助返回原“帮助”按钮，保留尚未保存的输入。独立运行 21 项帮助与会话回归全部通过。在真实 Edge 上测试真正的窗口回焦、会话服务暂失、重试和浏览器历史缓存，两种屏宽的四组回退中均未显示就诊内容。集成版本另跑帮助、声音组及新页面的 17 项用例均通过，有一条依赖弃用提示。[帮助交互回归](../../tests/test_partial_draft_help_playwright.py)
