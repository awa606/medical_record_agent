# 新问诊中的事实归属、检索原文与四位医生的并行接诊

本轮源基线为 `22c7770`，全部病例和账号均为工程模拟。维护版增加了医生检索抽屉中的来源计数、版本选择，以及可以在空环境重复执行的多账号接诊验证。两种事实归属规则和一个文书适用性判断器仍在隔离研究区。

## 首答与规则分别产生了什么

固定项目的 Qwen3 4B 模型和默认提示词，对四份未用于开发的中文文本各取一次答复。模型以离线容器运行，无回退，模型清单 SHA-256 为 `359d7dd4bcdab3d86b87d73ac27966f4dbb9f5efdfcc75d34a8764a09474fae7`。事前检查本人主要症状、数值归属和陈述者，模型结构化首答符合 3/4，维护基线处理后符合 1/4。两种研究候选分别使用同样的四份响应复算，各符合 3/4。每题三个回放组的请求摘要、首答正文字节摘要相同，基线回放的字段、可读草稿与安全结果同实机回执逐一一致。

| 输入 | 首答、规则和医生可见结果 |
| --- | --- |
| 本人鼻塞、否认发烧，妹妹测到 38.4 度 | 模型写入鼻塞，没有给出发热候选。维护规则生成“发热待查”，安全检查未拦。两个研究版本去掉该候选；原答仍漏写本人否认发烧。 |
| 本人头痛、自己腋下量到 38.6 度，父亲嗓子疼 | 本人头痛和温度保留，未把父亲嗓子疼写给患者。本项只评价事实归属。 |
| 本人手腕疼，35.8 度为保温箱读数 | 模型写入手腕疼，没有给出发热候选。维护规则生成“发热待查”，安全检查未拦。两种研究版本去掉该候选。 |
| 家属说自己前两天发烧，患者说自己右耳疼 | 模型把家属的话写到患者的结构化主诉。这一值仍在三种处理后的字段中，可读草稿均显示“待核对（模型内容未采纳）”，安全检查拦截主诉证据冲突。 |

另行封存的 18 例普通医生 R1 工作流用模拟提供方验证。事实及引用整例符合 6/18 → 8/18，第二候选仍为 8/18，但一项此前消除的咳嗽误记再次出现。独立第二批 10 例为 3/10 → 6/10 → 6/10，亲属药敏仍可能进入患者结构化事实。现有 60 例仍记录一个既有硬门槛失败，研究候选没有达到临床放行条件。

针对现病史陈述者另做了独立试验。八份新问诊中，同时保留主要症状和恰当陈述者的由 0/8 升至 6/8，八份候选都避免了无依据地写作“患者自述”。但有一例仍将家属症状建成患者事实；既有 60 例中又出现跨句回答“没有”的新退步。该试验保留原始回执与失败断言，未进入维护版。

## 医生查看检索原文

普通医生的同一查询从当前试库取回 5 个片段，实际来自两份资料。旧版需要逐卡比较文档和版本，首个界面试验重复列出 5 个链接。当前界面按文档 ID 和版本归并，对有身份且有可用原文的多个资料提供可折叠目录；身份信息不完整时只报片段数，单份材料保留卡内原文入口。正常实测与旧版使用同一检索 HTTP 响应，病历修订摘要相同。同名不同版本、来源地址缺失、旧格式与空结果均单独检查。

自动判断条款能否回答问题的另一候选在开发 10 题符合后，独立 16 题仅符合 9 题。8 道文书题的条款全在前五，但仅 2/8 得到正确支持。8 道涉及个体或医院许可的问题有 7 道标为依据不足，另 1 道被误标有文书依据。维护版不使用此候选进行判断。

## 四个账号正常接诊

在装有项目开发依赖的环境中运行以下命令。每组自行启动回环服务、创建四个普通医生账号和临时数据库，输出目录须是新路径。生成使用模拟提供方，除合成测量 JSON 外无需保留运行状态。

```powershell
python -m scripts.benchmarks.verify_concurrent_visits .artifacts/concurrent-visits-local
```

逐人及并行两组各有三轮，每个医生每轮创建一份独有病历，修改 R1 为 R2、批准、导出、读取 PDF，并在整组结束后重新取回。检查的内容包括正文中的唯一合成编号、修订与批准关系、批准人与导出人、文件字节摘要。在 Windows 的基线测量中，每组均得到了 12 份匹配的已签原件、24 条修订、12 个批准及 12 次导出。并行组三波中保存请求最多同时在途 2、2、3 个，批准及导出各波均达 4 个；轮流组均为 1 个。连接数量与测得响应时间描述当次单机软件环境，医院现场仍须约定真实操作组合、并发目标与恢复要求。

现有 CI 在 Ubuntu 24.04 运行同一源码和配方，并上传仅含合成操作与摘要的两份 JSON。网络、运行机器和临床条件须分别记录。正式成绩、真实临床配对使用权限、医生审阅结果及院方联调放行仍由相应审核方确认。
