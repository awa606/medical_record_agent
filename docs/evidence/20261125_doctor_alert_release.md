## r4.5 的两端服务和首次失败原件

固定 Debian 12 镜像在禁网容器中运行同一 ZIP 的源码，Windows Edge 158 经本机回环转发访问容器服务，容器无发布端口。普通模拟医生查看原包腕痛及一份另存的合成历史资料，两个病历、三种宽度共六次显示核验。首次只恢复 SQLite，因缺来源转写文件，导出被 HTTP 409 拒绝；按原始摘要补回同一合成录音的转写侧文件后，两份尚未通过审核的 R1 真实导出均以 HTTP 400 拒绝，并分别列出其就诊状态及既往史冲突。两份 R1 的内容和修订数前后相同。[最终回执与复算](20261125_alert_platform_checks.json)

Windows → Debian → Debian → Windows 四批采用相同的合成数据备份和端内真实 HTTP 客户端。每批每字段预热 5 次、正式 30 次，全程 240 次正式查询均成功。含预热的 70 组四批对应查询，命中内容与来源登记一致。合并每端每字段 60 个正式样本得到以下结果。

| 字段 | Windows P50 / P95 | Debian P50 / P95 |
| --- | --- | --- |
| 主诉 | 58.661 / 62.785 ms | 16.750 / 18.994 ms |
| 未填写的过敏史 | 57.964 / 63.753 ms | 16.852 / 19.491 ms |

该结果是同一主机、单模拟医生串行查询。原 r4.4 另做 Windows 路径归因，两个观察批次的认证、任务和就诊读取分别各执行一次数据库初始化，累计占各批 HTTP 时间 39.65% 和 38.86%，均低于预登记的过半主因标准。r4.4 与 r4.5 在不同时间测得，以上读数不能归因为文字改动带来提速。
