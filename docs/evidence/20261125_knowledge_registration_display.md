# 医生能从资料卡判断它适用于什么问题吗？

2026 年 11 月 25 日，MediListen r4.4 在字段知识和诊疗参考两个入口显示同一版本的资料类别、登记用途和可查询的主题。演练使用合成腕痛病历。两个版本都会检索到门急诊诊疗信息页保存期限；这条文书规定可用于核对保存对象和期限，对个体腕痛的病因没有直接证明力。

## 应用如何保留来源

- 检索沿用基于 `document_id` 的既有版本登记表连接。增加的 `document_type` 和 `disease_scope` 来自返回片段自己的版本。同一来源的另一稿可单独登记。
- 两个入口把类别、用途与摘录放在一起；主题和校验值可展开。新版称“参考资料”。逐版本、旧库共用以及缺少出处的元数据分别用可见文字说明。通用的 `clinical-reference` 只按通用分类呈现。
- 原有关联记录中的 `evidence_scope` 描述这次关联的适用范围。资料管理的 `usage_scope` 描述登记用途。每项只在有相应来源时呈现，空值保留缺失提示。历史结构中的 `source_type` 与版本登记的 `document_type` 分属不同对象。
- HL7 FHIR R4 文档引用也把文件类别和上下文写作不同属性。本轮参考这一区分，实施范围未涉及 FHIR 互操作认证。[规范字段定义](https://hl7.org/fhir/R4/documentreference-definitions.html)

## 两次合成就诊的检索边界

在两套独立回环 HTTP 服务中导入同一批初诊、复诊材料，普通模拟医生从登录、签到和提交各自问诊开始。原版为 `99eeacb`，候选为相同代码仅替换本次知识服务文件。每版在四种发布状态各执行 26 次查询，共 104 次，返回 348 条片段。两版的片段、摘录、顺序与打分逐条一致。

| 合成问题 | 实测 |
| --- | --- |
| 初诊书写、复诊书写、时间精度、急诊时间四项文书问题 | 自由查询对应条款排名依次为 2、2、1、2。给定初诊或复诊任务后为 2、1、1、3。 |
| 患者病因、具体药名、症状归属、正式超声结论 | 分别返回 3、4、3、3 个片段。四题均无可证明该患者答案的条款。 |
| 同一来源两个版本 | 管理员新稿在启用前只可预查，启用后显示新稿的自定义类型和主题。回到原稿读到原来的病历规范及门急诊书写范围。两次就诊的原始 R1 均未改写。 |

## 正式包的独立核验

同一份合成腕痛记录在 1366、390 和 320 像素宽度分别从主诉、过敏史和右栏打开；每处两条资料。逐版和旧库共两种登记方式，一共 36 次观察，能逐字读到用途，也能核对类别、主题、版本、摘录、原链接及校验值。旧版右栏在这 12 次观察中均缺登记用途。另一份持久化的合成历史关联记录可按两个正常入口回查原适用范围。停用唯一活动文档后病例检索为零，重新启用读回两条。旧包重开原库时，十项版本、会话和内容标识逐项一致。三宽分别断网下载、核对了实物包；七张实屏嵌入的课堂页也在三宽下经键盘展开检查。[机器可读结果及原始回执指纹](20261125_knowledge_registration_display.json)

### 同一提交在两个操作系统的测量

Windows 11 与同一台机器的 Debian 12 容器分别运行 r4.4，容器禁网。单普通模拟医生串行发起真实 HTTP 回环请求，每端每字段预热 5 次，正式计时 30 次。共 120 次正式请求均返回 HTTP 200；含预热的 70 对响应，片段正文、排序、分数和资料登记相同，原病历 R1 操作前后相同。

| 环境 | 主诉 P50 / P95 | 过敏史 P50 / P95 |
| --- | --- | --- |
| Windows 11 | 143.617 / 161.998 ms | 142.642 / 182.956 ms |
| Debian 12 | 50.812 / 67.567 ms | 47.718 / 68.752 ms |

本机两端功能结果一致，Windows 的这两组 P95 均高于 Debian。并发量、网络环境和目标院方硬件需另设试验。医生判读效果及学校评分由对应评阅者填写。
