# 门诊工作台前端对照与入口取舍

MediListen r4.5 继续使用字段卡上的原文与书写资料入口。试验表明，医生在资料内切换到同一字段可以少一步。在窄屏上，动作占去的高度会直接挤掉正在阅读的原文。是否更适合普通医生，要一起观察首次找到入口与读对摘录的表现。

## r4.5 五种摆位的实际代价

使用同一版应用、合成就诊、相同字段与命中资料，在 Windows Edge 对照原布局及隔离修改。下表限 320 × 640、多来源长摘录场景。“可见高度”指打开资料后，第一段摘录在视口中实际可读的 CSS 像素。操作从已打开资料的同一状态起计。键盘按约定顺序记录，人工滚动与寻找耗时待实测。

| 布局 | 点击 / 按键 | 首屏可见摘录高度 | 决策 |
| --- | --- | --- | --- |
| A · 现版两个入口 | 2 / 4 | 147.81 px | r4.5 默认 |
| B · 顶部按钮 | 1 / 3 | 100.62 px | 损失 47.19 px |
| Bt · 顶部文字按钮 | 1 / 3 | 111.81 px | 控件改为文字后仍占首屏 |
| D · 检索说明末的文字按钮 | 1 / 3 | 123.81 px | 先供医生试用，核对读到的原文与找到入口的时间 |
| E · 第一段摘录后 | 自动滚入视野后 1 / 4 | 147.81 px | 动作顶边在 y = 815.50 px，首屏不可见 |

可复核各宽度的对应读数、两批原始观察数量及文件摘要。[逐宽实测回执](20261125_outpatient_layout_measurements.json)

主体试验共 144 条路径，覆盖四个布局、三个宽度（1366、390、320）、六种字段与资料条件、两种输入方式。附加 15 条路径核对摘录后入口及未保存编辑。主体方案实测了检索失败后重试、切换到另一位合成患者再释放迟到结果，以及关闭后焦点返回。390 和 1366 宽的该组长摘录均完整显示。五种摆位是设计试验，已交付 r4.5 的应用提交为 `a2f6c3120eb82d36eceeaa53b3fffc0ef5d1e20a`。[同版软件与两端实测](20261125_doctor_alert_release.md)

## 医生试用要记录什么

在同样的设备上分别给 A、D 两个布局安排等价的合成就诊，交换两种布局的先后顺序。给医生的任务只描述目标，例如找出患者哪句话支持主诉，或指出所引资料允许哪种书写用途。主持人记录首次独立完成、寻找时间、误点、是否读对原句、返回后的字段以及是否保留未保存编辑。遇到无引文或旧引文时，另记医生把依据判成了哪一类。各宽度单列结果。此次实测未获得医生试用回执。
