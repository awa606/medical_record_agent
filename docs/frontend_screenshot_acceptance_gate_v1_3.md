# 医生端截图验收门禁（v1.3 起执行）

## 当前 Alpha 5.1 规则（2026-09-26）

本节取代下方历史 v1.3 的布局与发布口径，历史记录保留。

- 当前为左侧转写、中间病历、右侧诊疗参考三栏；转写正文16px、病历正文17px。后续功能必须明确归属已有区域，不在接业务时重建布局。
- 右栏默认只显示“诊断参考”名称和“治疗参考”标题。长理由、引用、检查、风险及用药信息在详情面板读取；不再使用等高卡片或卡片内部滚动。无单项关联的资料标为“病例级参考”。
- 新增功能改变布局骨架时，必须展示同一匿名病例的前后效果。截图差异须人工认可，不运行自动更新基线来消除失败。
- 真实医生页面覆盖1366×768、1440×900、1920×1080；另测真实Edge 125%／150%缩放及Chrome。等效小视口测试不能替代实际浏览器缩放。
- 详情必须支持关闭、Esc、键盘焦点返回与编辑缓冲保留。角色、证据、Revision和审核阻断仍在主状态／操作区显示。
- 按用户批准的本轮计划，可以将实现及待认可截图证据推送Draft PR #113；人工视觉门禁未完成时保持5.1 VERIFY，不更新截图基线、不冻结稳定版本。新版必须重新生成与Git SHA一致的恢复候选。
- 截图及原始测试日志保存在本地受控`.artifacts`；Git记录匿名摘要、文件SHA及来源，不提交录音、数据库、模型或身份资料。

本轮设计见[参考栏与导航视觉修正](design_reviews/20260926_alpha51_reference_sidebar.md)。

## 历史 v1.3 规则

从 v1.3 开始，所有涉及医生端前端、输入流程、转写流程、病历生成流程的迭代，都必须完成截图验收后才能提交。

## 必须截图的状态

- 空态首页：未上传、未导入文本。
- 输入方式：打开输入方式选择或输入弹窗。
- 转写中：至少包含进度、转写列表或等待提示。
- 生成后：左侧病历草稿、中间转写、右侧 AI 辅助均有内容。
- 详情抽屉：字段详情、证据、质量判断或导出阻断原因。
- 导出阻断或导出成功：至少覆盖一种导出状态。

## 必须覆盖的视口

- 1366x768，浏览器 100%。
- 1920x1080，浏览器 100%。

## 自查清单

每张截图都要记录：

- 是否存在遮挡或重叠。
- 是否出现横向溢出或不必要的页面级滚动。
- 信息是否过多，医生是否能一眼看到下一步。
- 主按钮是否清楚可见。
- 详情是否进入弹窗/抽屉，而不是堆在默认界面。
- 本次迭代目标是否达到。

## 证据保存路径

截图按版本保存到：

```text
docs/final_report/images/v1_3_xxx/
```

验收结论写入当天 daily log 和 `docs/能力证据追踪矩阵.md`。

## v1.3.0 本轮重点

- 流程条第 5、6 步不遮挡。
- 详情抽屉默认不覆盖整个工作区。
- AI 辅助区内容多时只在卡片内部滚动，操作区始终可见。
- 查体字段不再把医生追问、患者既往史、家族史误写入查体。
