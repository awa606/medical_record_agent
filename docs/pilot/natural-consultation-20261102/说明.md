# MediListen自然门诊对话测试材料

先用[文本输入版](文本输入版.txt)测试真实字段提取，再由两人使用[双人朗读稿](双人朗读稿.txt)录音。两份台词完全相同，仅排版不同；[事实核对表](事实核对表.md)单独使用，不要粘贴进病历输入框或朗读给系统。

病例编号：`SIM-NATURAL-ADULT-20261102`。内容为原创合成的成人发热咳嗽问诊，不含真实患者资料。正文约1100汉字，目标约5分钟；尚未实际录制，准确时长由朗读速度、停顿及录音结果决定。

## 怎样使用

1. **先确认入口是真实服务。** 使用本轮验收后登记的“本地FunASR＋DeepSeek在线生成”入口。26324／26326是固定历史响应回放，不能用本稿评估新输入；26320的Mock演示也不代表真实模型能力。以本轮交付记录中的实际入口和版本为准，不凭页面外观判断。
2. **新建匿名就诊。** 将文本输入版完整复制，保留“医生：／患者：”行首。不要混入核对答案或为让系统通过而删除患者的补充与纠正。
3. **只生成一次并保留首次结果。** 核对发热时间、一次布洛芬、未服阿莫西林、否定信息和父亲病史；分别记录首次结果、规则隔离和医生修改。
4. **完成实际核对。** 查看引用→修改有依据的内容→保存新版本→查看旧版→处理缺失与冲突→审核→导出→重开。没有做查体时不要为了通过而填写“查体正常”。
5. **再测试录音。** 两个人分别朗读医生和患者，角色标签不用念。按自然音量交谈，不必刻意逐字放慢，也不必把每个句号读成很长停顿。首次测试不要故意重叠说话或额外添加未记录的症状。
6. **区分错误来源。** 先对照录音与转写，再对照转写与字段；保留第一次出错位置，不反复点击生成挑选最好的一次。网络生成失败与内容错误也分别记录。

录音是否达到5分钟不作为模型质量标准。真实麦克风、转写质量和角色识别只有实际执行后才能填写结果；本文档制作完成不代表这些项目已通过。

## 为什么这份稿更接近日常交流

患者先讲“夜里睡不好、怕影响明天开会”，再在追问中回忆时间和家庭用药；医生响应担心、澄清情况、复述确认，没有一开口就按七个病历字段点名提问。稿中保留一次时间纠正和一次用药补充，同时保留检查尚未进行、剂量不清楚等正常的信息边界。

这里的布洛芬是患者在合成情境中的既有用药叙述，不是给读者的服药建议；稿件没有给出确定诊断、具体处方或药物剂量。

## 材料与结果分别保管

| 文件 | 用途 |
| --- | --- |
| `双人朗读稿.txt` | 两人排练、录音，段间留空行 |
| `文本输入版.txt` | 完整粘贴输入；每个发言一行，共40行 |
| `事实核对表.md` | 先固定预期，再逐字段核查；不作为模型输入 |
| `说明.md` | 测试顺序、入口边界与材料来源 |

实际音频、模型原始响应、页面截图、病例和导出文件保存在本轮本地验收目录，不随这组公开合成测试材料自动上传。交付报告记录实际运行版本、输入哈希及证据位置。
