## 最短现场主线

教师先按现有T01病例操作：

1. 桌面“教师现场试用”进入8798，使用普通医生账号。
2. 工作台新建匿名就诊并报到，开始接诊，选择文本输入。录音作为另一路体验，不用录音权限故障卡住全部讲解。
3. 生成一次，核对原文与字段。缺失和冲突按实际说明，不连续点击生成以挑成功结果。
4. 修改一项内容、保存新版本，打开“历史版本”查看修改前后。
5. 核对当前版本、批准、导出并实际打开DOCX，再从工作台重开同一就诊。
6. 由组织者展示管理员知识目录、一个指南来源和数据查看器两条关联链。普通医生不需要管理知识、操作数据库或Docker。

历史备用明确标注生成时间、模型和人工修订，不冒充现场推理。断网时停止DeepSeek新生成，仍可讲解已保存病历、原文、已索引知识和既有导出。

## 本轮恢复准备的选择与限制

比较现有三条途径：旧完整Qwen包会改变当前Provider且重复复制模型；18028空库候选适合修复验收但不是完整恢复；现有镜像加容器内一致性备份和明确关联文件可以准备当前在线版的数据副本。选择第三条作为隔离验证方向，尚不写恢复PASS。

- 复用当前精确镜像，不构建、下载或重新导入旧模型大包。
- SQLite副本在源Linux容器内用Backup API生成、关闭后复制；不从Windows直接打开Linux活动WAL。
- 只复制明确的运行数据目录，逐文件校验；独立账本继承累计费用与原预算，不重置计费。
- 去除工作副本登录会话，原封存备份保持；副本及账号哈希只留本地，凭据原件不复制、不读取或发布。
- 既有语音/知识模型缓存及密钥继续作为明确的只读外部依赖。准备完成只能证明这些依赖下可用的恢复输入，不能称自包含跨机离线包。
- 当前浏览器工具无法可靠识别Edge网址并停止控制。本轮不暂停8798，不把接口或准备脚本成功替代新环境实际按钮和截图通过。
