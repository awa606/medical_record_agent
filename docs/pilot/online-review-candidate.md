# 在线审核候选使用说明

本入口沿用登记、输入、核对、修改保存、审核、导出和历史重开的流程。使用前应看到“**在线审核候选 · DeepSeek 云端生成（需联网）· 本地 FunASR 转写**”。这表示转写在本机完成，病历字段生成调用云端服务；不是完整离线版，也尚未放行独立医生试用。

## 医生和演示人员

1. 打开登记好的当前版本桌面入口，点击“启动服务”。只使用合成或已授权的去标识测试材料。
2. 看到“运行就绪”后打开工作台。就绪只表示服务可用，不代表生成内容已正确。
3. 正常登记、输入并核对病历；遗漏、冲突或生成失败如实显示。医生修订、保存及分项审核后再导出。
4. 网络、鉴权或服务失败时，保留输入与历史记录。系统不会自动改用 Mock 或本地模型冒充成功。
5. 需要切换另一登记环境时，先保存或取消编辑，结束录音、等待任务完成并退出页面，再使用“切换到本版”。不通过反复点击或修改配置绕过阻断。

知识管理、数据与知识查看器及内嵌帮助入口保持原位置。查看器是当前环境的只读快照，不代表实时业务库。

## 维护登记

在线候选继续使用现有控制器和窗口，不安装新启动器依赖。先由维护人员建立和验收固定 Compose 项目，再登记已运行的容器。示例中的项目名和配置文件必须替换为本机已经验收的实际值：

```powershell
python scripts/doctor_pilot.py configure --provider-profile online_deepseek --project <已验收项目名> --port 8798 --config <新的本机私密配置文件>
powershell.exe -NoProfile -STA -File scripts/Start-DoctorPilot.ps1 -Config <新的本机私密配置文件>
```

登记后沿用现有双环境配置流程，设置并核对两端的 `peer_config`、同一 `switch_lock`、独立数据目录及 Cookie，再提供日常桌面入口。控制器不会猜测或自动停止其它环境。旧本地入口保留作维护回退，旧归档不覆盖；不把两个活动入口同时提供给使用者。

在线配置固定 `online_deepseek`、`ONLINE_LLM_PROFILE=deepseek_demo`、`live`、`deepseek-flash`、本地 FunASR、零自动重试和启用脱敏。官方地址仅接受 `https://api.deepseek.com` 或 `https://api.deepseek.com/v1`，登记精确值后不允许静默变化。模型服务密钥只留本机运行配置，不写入启动器登记、日志或版本库。当前部署采用 `/run/secrets/deepseek.env` 的只读文件挂载；启动器只核对文件位置和挂载，不读取密钥或计算其哈希。费用与诊断资料使用 `/app/online-private` 独立可写挂载，禁止悄悄改到新账本路径来绕过已使用费用。

没有 `provider_profile` 的旧配置继续按 `local_qwen` 验证固定 Qwen 缓存，不会自动变成在线版。在线配置只管理应用与网关两个服务，不要求或启动 Ollama。已有容器、镜像、挂载、页面资源或 Cookie 发生变化时必须重新登记，不能修改旧指纹来掩盖版本变化。

## 失败时怎样处理

- **另一环境正在运行**：先处理当前内容，再走受控切换。
- **版本或页面指纹不匹配**：停止打开入口，由维护人员核对配置与镜像。
- **网页可用但在线生成未就绪**：检查网络、鉴权与本地转写；可继续查看历史，不将此状态视为生成成功。
- **模型内容遗漏或冲突**：保留首次结果，按实际医生修订流程处理；接口连通不代表模型质量达标。

上线、恢复及产品质量仍需分别验收。本说明不替代本地 Alpha 的离线验收要求。
