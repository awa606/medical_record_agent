# R-2.1 浏览器真实录音基础链路研究

> WBS：2.1 · 浏览器真实录音基础链路整合
> 日期：2026-09-18
> Research Gate：**PASS**
> Reuse Decision：**REUSE**

## Problem

Alpha 2.1需要证明当前医生工作台能在真实浏览器和物理麦克风上完成开始、停止、试听、提交和取消，并在提交后取得后端音频标识。任务不要求重新实现长录音、断线恢复或2.2真实ASR质量验收。

## Existing Internal Solution

- PR [#53](https://github.com/awa606/medical_record_agent/pull/53) 已合入浏览器录音MVP。
- PR [#66](https://github.com/awa606/medical_record_agent/pull/66) 已合入可恢复分块录音。
- `static/doctor.js` 已使用 `navigator.mediaDevices.getUserMedia`、WAV编码、分块上传、试听、完成和取消接口。
- `app/api/asr_sessions.py` 已实现录音分块、完成、取消、幂等和音频标识。
- Issue [#42](https://github.com/awa606/medical_record_agent/issues/42) 已明确为V2长录音与恢复范围，不代表MVP尚未实现。
- 本轮定向自动回归：`60 passed in 61.30s`。

## External Candidates

| Candidate | Evidence | Fit | Integration cost | Security / maintenance |
|---|---|---:|---:|---|
| A · 复用原生 `getUserMedia + MediaRecorder` | [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)、[MDN MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder)；当前仓库已有完整实现 | 5/5 | 5/5 | 浏览器原生权限模型；localhost属于可信上下文；无新增依赖 |
| B · 适配 AudioWorklet | [MDN AudioWorklet](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet)；适合低延迟自定义音频处理 | 3/5 | 2/5 | 需要额外线程处理、编码与兼容测试；对基础录音没有已证明收益 |
| C · 引入 RecordRTC | [RecordRTC GitHub](https://github.com/muaz-khan/RecordRTC)；MIT，封装MediaRecorder | 3/5 | 2/5 | 新增第三方依赖和接管面；当前原生实现已覆盖所需操作 |

评分只针对2.1基础录音范围。真实麦克风Spike已完成，现有原生实现满足本任务，不引入新录音框架。

## Unknowns

- **U01（决策关键）**：DEV-01的Edge能否取得物理麦克风权限并采集5–15秒真实音频。
- **U02（决策关键）**：真实录音停止后是否可试听并取得后端音频标识。
- **U03（决策关键）**：取消流程是否不会创建提交任务或残留音频。
- U04：Chrome回退能力；当前主机未向自动化环境提供Chrome，非Edge主路径阻塞项。

## Minimal Spike

**Hypothesis H-REC-01**：现有原生录音实现无需生产代码修改，可在DEV-01 Edge中完成真实短录音、试听、提交和取消。

- Input：匿名就诊`SIM-REC-20260918`；不含身份信息的固定测试语句。
- Environment：Windows DEV-01、Edge、`http://127.0.0.1:8765`、本地临时SQLite/上传目录、Mock ASR（只验证采音与上传，不声称2.2通过）。
- Metrics：权限结果、真实录音时长、试听可用、后端`session_id/audio_id`、取消后的任务和文件数量。
- Pass：五种基础操作可执行；提交产生音频标识；取消不误提交且无残留业务音频。
- Stop：浏览器级权限未获批准、没有物理麦克风或核心链路报错。

## Decision

**REUSE。** 复用现有`getUserMedia + MediaRecorder/WAV编码 + 分块上传`链路。Research Gate为`PASS`；AudioWorklet和RecordRTC没有为2.1带来已证明收益。

## Fixed Questions

1. **别人是否已经解决过？** 是；浏览器标准API、PR #53/#66及当前服务均已覆盖基础链路。
2. **能否直接复用？** 可以；真实Edge与Realtek物理麦克风已完成基础操作和后端持久化验证。
3. **最大风险是什么？** 后续2.2真实ASR质量与长录音恢复；两者均在2.1范围外。
4. **最低成本怎样验证？** 已执行一次13.397333秒真实录音提交和一次真实录音取消。
5. **证据是什么？** 当前源码、PR #53/#66、浏览器UI、服务端session文件、WAV元数据与SHA、取消清理和本轮回归测试。
6. **为什么选择REUSE？** 现有实现直接满足2.1全部验收；ADAPT没有已观察缺陷，BUILD会引入不必要依赖与回归面。
7. **判断错误时怎样回退？** 若真实Spike暴露局部缺陷则ADAPT现有实现；只有浏览器原生方案存在不可修复兼容问题时才评估AudioWorklet或RecordRTC。

## Gate Result
