# R-2.3 医患角色门禁研究决策

> 日期：2026-09-19
> WBS：2.3 医患角色判断与质量门禁
> 基线：`main@bfcd367af163905dec9aad787c814692a830d424`
> Research Gate：**PASS**
> 决策：**ADAPT**

## Problem

WBS 2.3 要解决的不是重新训练说话人模型，而是证明现有真实 FunASR、CAM++、角色质量策略、人工映射和生成门禁能够形成可恢复且不可绕过的闭环：角色未确认时阻止病历生成，医生确认全局 `speaker → doctor/patient` 映射后重新校验并允许流程继续。

Issue #41 的正式大样本准确率、覆盖率和高置信度错误阈值仍需后续冻结数据集验证。本轮仅判断 Alpha 所需闭环是否成立，以及普通医生页面是否有必要做有限适配。

## Research Questions

1. 现有后端是否已经具备角色识别、质量判定、人工映射、审计和不可绕过门禁？
2. 普通医生工作流能否在收到角色质量 `409` 后找到并完成身份确认？
3. 双人正例和单人负例能否用真实本地模型形成可追溯证据，而不依赖 Mock、固定文本或云端回退？

## Existing Internal Solution

仓库审计确认已有能力：

- CAM++ 说话人聚类与 diarization 结果增强。
- `speaker-role-policy-v1`、`role_quality`、pending speaker 和 reason code。
- `PATCH /api/asr/sessions/{session_id}/result` 的全局说话人角色映射。
- 人工映射写入 `manual_speaker_map`、置信度 `0.99`，并追加 `role_reviewed` 审计事件。
- `POST /api/audio/{audio_id}/generate-record` 在角色质量未通过时返回 `409`。
- 医生端已经有身份确认抽屉、保存逻辑、PATCH 调用与错误解析。

已确认的缺口位于普通医生页面：原逻辑把 `roleReviewRequired()` 固定为 `false`、pending 数量固定为 `0`，导致后端正确阻止后缺少可见恢复入口。该缺口不要求修改后端契约、数据库、阈值或模型。

## Candidate Matrix

| 候选 | 功能适配 | 真实证据 | 集成成本 | 安全与回退 | 结论 |
|---|---|---|---|---|---|
| REUSE：现状不改 | 后端闭环完整，但普通医生页面不能可靠进入恢复流程 | API 正负路径成立；页面入口缺失 | 低 | 会把医生留在不可恢复的 `409` 状态 | 拒绝 |
| ADAPT：复用后端，只补条件式医生恢复入口 | 覆盖角色确认、重新校验和继续生成 | 双人正例、单人负例、两次直接 API 绕过检查均已实测 | 低；局限于 `static/doctor.js` 与对应测试 | 保留 fail-closed、五步流程和现有接口 | **选择** |
| BUILD：新模型、新角色服务或新步骤 | 能做，但超出 Alpha 所需闭环 | 没有证据表明现有后端契约失败 | 高 | 增加新模型、接口和回归面 | 拒绝 |

## Minimal Spike

输入由两段无身份信息的双人片段和一段真实单人录音构成。音频、RTTM、SQLite、日志和完整结果只保存在本地忽略目录；Git 仅记录 SHA256、匿名指标和结论。

流程：

1. 用现有真实 FunASR 和 CAM++ 处理三段音频，禁止 Mock、固定文本和云端回退。
2. 双人样本在严格策略下保留 pending speaker，连续两次直接调用生成 API。
3. PATCH doctor/patient 全局映射，核对 `manual_speaker_map`、`0.99`、pending 归零及 `role_reviewed`。
4. 再调用生成入口，确认门禁允许任务进入队列。
5. 单人反例重复直接调用，确认仍不能绕过。

### Measured Results

| 样本 | Speaker count error | Boundary F1 | Mixed utterance rate | Role consistency |
|---|---:|---:|---:|---:|
| 发热双人片段 | 0 | 0.5294 | 0.2857 | 0.8838 |
| 胸痛双人片段 | 0 | 0.3846 | 0.3750 | 0.8780 |

两个双人样本的严格策略初态均为 `needs_review`、pending 2；每个样本两次未确认生成调用均返回 `409`。PATCH 后均为 `passed`、pending 0、`role_reviewed` 事件 1 条，并接受一个生成任务进入队列。该队列使用本地 Ollama 配置建立，但后台 LLM 任务未执行，因此不构成病历生成质量或 LLM 成功证据。

单人反例为一个 speaker，严格策略状态为 `blocked`，reason code 为 `single_speaker_counterexample`；两次直接生成调用均返回 `409`。

## Decision

选择 **ADAPT**：保留现有 FunASR/CAM++、角色策略、PATCH、审计和生成门禁，只在普通医生五步工作流中恢复一个条件式“确认说话人身份”入口。只有 `role_quality` 需要复核或存在 pending speaker 时显示；保存后必须同时满足 pending 为 0 且质量门禁通过，才能继续生成。

- 不选 REUSE：后端虽然完整，但普通医生页面当前没有可发现的恢复入口。
- 不选 BUILD：真实 Spike 已证明后端契约可以完成正路径、负路径和防绕过，不需要新模型或新服务。
- 若后续正式样本证明现有 diarization 或角色策略无法达到 Issue #41 阈值，再重新打开模型与策略 Research；不改写本次闭环事实。

## Fixed Seven Questions

1. **别人是否已经解决过？** 项目内部已实现角色策略、质量门禁、PATCH 和审计，缺口只是普通医生恢复入口。
2. **能否直接复用？** 后端可直接复用；前端需要有限适配，因此不是完整 REUSE。
3. **复用最大风险？** diarization 边界质量仍有限，且小样本不能证明正式准确率和自动接受覆盖率。
4. **最低成本如何验证？** 两段双人真实音频加一段单人反例，复用现有 API 做两次 409、一次人工映射和一次排队验证。
5. **证据是什么？** 输入/结果/评测/角色 API 报告 SHA、匿名指标、两次 409、PATCH 结果和审计事件。
6. **为什么选 ADAPT？** 后端闭环已成立，唯一决策关键缺口是普通医生页面的条件式恢复路径。
7. **判断错了如何回退？** 撤回前端条件入口改动，保留后端 fail-closed；正式样本失败时重开 Issue #41 Research，而不替换多个层。

## Remaining Limits

- Boundary F1 和 mixed utterance rate 只作为本次样本测量，不宣称达到正式阈值。
- 自动接受覆盖率在严格策略初态为 0；本轮验证的是人工确认闭环，不是自动角色判定能力。
- Issue #41 保持打开，继续承担正式样本量、角色准确率 ≥95%、高置信度错误 0 和覆盖率要求。
- V02 只能按 Alpha 角色门禁闭环判定，不得被引用为 Issue #41 正式大样本完成。

## Research Gate

**PASS**。真实模型、双人正路径、单人负路径和不可绕过门禁已经提供足够证据，支持进入最小前端适配的 Engineering Design Review。
