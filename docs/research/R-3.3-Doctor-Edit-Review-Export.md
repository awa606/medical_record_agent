# R-3.3 医生修改、审核与导出研究记录

## 问题

WBS 3.3 需要在现有医生工作台上完成整页病历修改、字段证据查看、主动查询知识依据、Revision 保存、分项审核和受控导出。研究目标是判断现有实现能否直接复用，或只需有限适配。

## 约束

- 保留现有五步医生工作流和公共 HTTP API。
- 医生只能修改病历字段和候选诊断处置结果；原始转写证据、知识来源和审计记录只读。
- 修改必须生成新 Revision，使旧批准失效；旧 Revision 保存必须返回冲突。
- 未审核、角色未确认或证据冲突时不得导出。
- 不引入新前端框架、状态机、数据库表或医院级权限体系。

## 候选方案

| 候选 | 功能适配 | 改动成本 | 安全与回退 | 结论 |
|---|---:|---:|---:|---|
| REUSE 当前只读字段卡 | 2/5 | 5/5 | 5/5 | 无法满足整页编辑与主动查询 |
| ADAPT 当前页面和既有 API | 5/5 | 4/5 | 5/5 | 选用 |
| BUILD 新页面或前端状态机 | 5/5 | 1/5 | 2/5 | 超出 Alpha 范围 |

## 最小 Spike

**假设 H-3.3-01**：现有后端闭环可复用，决策关键缺口仅在医生页面的编辑和主动检索交互。

- 输入：匿名合成任务“患者发热39度，否认胸痛，没有花生过敏”。
- 环境：当前分支、临时 SQLite、现有浏览器测试服务。
- 测量：字段卡、可编辑控件、字段级知识查询入口、保存按钮和审核清单数量。
- 实测：字段卡 7；可编辑控件 0；字段级知识查询入口 0；保存按钮 1；审核清单 1。
- 证据：本地 `.artifacts/alpha33-research-spike/result.json`，原始运行数据不提交 Git。

Spike 证明审核与保存入口已存在，整页编辑和主动查询必须适配；无需新 API 或新框架。

## 决策

**ADAPT EXISTING DOCTOR WORKBENCH**

适配边界：

1. 在现有字段卡上增加整页编辑模式、未保存状态和取消编辑。
2. 编辑只更新字段值和医生修改标记，保留原始证据与知识引用。
3. 使用现有 Revision 条件写入；409 时保留本地内容并提示加载最新版。
4. 使用现有知识检索接口按字段查询，展示来源、版本、章节、页码、URL 和哈希。
5. 继续使用现有分项审核、批准失效和导出接口。

## 固定七问

1. 别人是否已经解决过？项目内部已实现 Revision、审批、导出和知识检索主体能力。
2. 能否直接复用？后端可以，当前只读页面不能完整复用。
3. 最大风险是什么？医生编辑值与原始证据边界混淆，或并发保存覆盖新 Revision。
4. 最小成本如何验证？用一个匿名浏览器任务统计编辑控件和知识查询入口，再复用现有真实 API 测试审核导出。
5. 证据是什么？内部代码、既有事务与浏览器测试，以及 H-3.3-01 实测。
6. 为什么选择 ADAPT？现有能力覆盖大部分闭环，只缺医生页面交互和冲突提示。
7. 判断错误如何回退？移除前端编辑适配即可恢复只读工作台，后端数据和 API 不变。

## Research Gate

**PASS**。关键 Unknown 已由内部审计和最小 Spike 关闭，决策为 `ADAPT`。
