# R-4.1 Knowledge Base V1 Research Decision Record

## Problem

补齐现有本地知识索引的管理、权限、导入和验收闭环，使管理员能安全管理版本化资料，医生只能检索已启用资料，并且每条结果都可追踪至来源、版本、章节、逻辑页和内容哈希。知识只作为医生参考证据，不成为患者事实证据，也不参与自动诊断、处方或批准。

## Constraints

- 归入既有 WBS 4.1，保持 16 项、99h，不新增 4.3。
- 本地离线优先，复用 SQLite、FTS5 和 `BAAI/bge-small-zh-v1.5`。
- 原始资料、SQLite、embedding 和模型权重不进入 Git。
- 导入只接受 UTF-8 TXT/Markdown，不主动下载远程 URL。
- 新导入默认停用；管理员测试后显式启用。
- 现有 HTTP 读取接口保持兼容。
- 最终 T11 仍需 120 条复核查询和 40 条片段级冻结集，本轮 40 条工程集合不能替代它。

## Research Questions

1. 当前仓库已有知识能力能否覆盖索引、检索和引用追踪？
2. Issue #71 尚缺哪些管理、权限和前端能力？
3. 是否存在引入独立向量数据库的决策关键缺陷？

## External Candidates

1. **SQLite FTS5**：官方内置全文检索虚拟表、MATCH 和 BM25，当前仓库已使用。来源：<https://www.sqlite.org/fts5.html>。
2. **BAAI/bge-small-zh-v1.5**：当前轻量中文 embedding 派生索引。来源：<https://huggingface.co/BAAI/bge-small-zh-v1.5>。
3. **独立向量数据库**：Qdrant、Milvus、Chroma 或 Elasticsearch。它们可以扩展规模，但会新增服务、运维和一致性边界；当前 30 个正式片段和本地单机场景没有证据需要它们。

## Unknowns

### U01：兼容迁移

旧数据库增加元数据和启停字段后能否无损读取。用旧 schema fixture 执行迁移测试回答。

### U02：停用泄漏

词法、向量、来源列表、任务证据和医生检索能否一致排除停用文档。用同一数据集覆盖所有路径。

### U03：管理边界

管理员、医生和匿名访问能否稳定返回 2xx/403/401。用真实 FastAPI 路由测试和浏览器 API 调用回答。

## Minimal Spike

- Hypothesis：现有 SQLite/FTS5/BGE 能在不引入新服务的情况下满足 Knowledge V1 检索门槛。
- Input：3 份发热/呼吸官方资料、30 个片段、20 条开发查询。
- Environment：开发机本地 SQLite，FTS5 与本地 BGE 缓存。
- Procedure：分别运行 FTS5 与 hybrid 检索，统计 source-level Recall@5、引用完整率和无来源引用。
- Metrics：Recall@5、citation completeness、source-less citation count。
- Pass Criteria：Recall@5 ≥90%、引用完整率 100%、无来源引用 0。
- Stop Criteria：索引不可重建、来源追踪丢失或必须依赖远程服务。

## Measured Results

历史已执行 Spike：

- FTS5 Recall@5：`95% (19/20)`。
- Hybrid Recall@5：`95% (19/20)`。
- 引用完整率：`100%`。
- 无来源引用：`0`。
- 结果边界：开发集为来源级标签；不构成最终 T11 PASS。

## Decision

**ADAPT EXISTING KNOWLEDGE STORE**。

复用当前 schema、FTS5、BGE、匿名化和医生读取接口；新增兼容迁移、管理领域函数、管理员 API、TXT/Markdown 导入、启停过滤、管理 UI、健康/测试搜索及固定冻结检查集。

## Rejected Alternatives

- **REUSE 原样使用**：Issue #71 的管理、启停、导入和权限闭环缺失。
- **BUILD 新检索系统**：现有检索已达到本轮工程门槛，自研会重复实现索引与引用。
- **引入向量数据库**：当前规模和离线约束下没有决策关键收益，增加部署和数据一致性风险。

## Risks

- 新版本默认停用时误下线旧版本。
- 停用只影响某一检索路径，形成来源泄漏。
- 管理员 PATCH 覆盖内容、版本或 SHA，破坏可追踪性。
- 浏览器导入未经编码、大小和转义检查。

## Implementation Boundary

只实现 Issue #71 的 Knowledge V1 管理闭环。不实现远程下载、PDF/DOCX 解析、知识图谱、Agentic RAG、自动诊断、自动处方、知识自动写入病历事实或大型向量数据库。

## Rollback

所有 schema 变更只增列和增表；旧数据默认启用。失败时回滚本分支代码，保留原数据库备份。启停只改状态，不删除文档、chunk、embedding 或历史引用。

## Fixed Questions

1. **别人是否已经解决过？** 项目内部已解决版本化索引、FTS5/BGE 检索和引用追踪；官方组件覆盖基础检索能力。
2. **能否直接复用？** 核心检索可以复用，管理闭环需要适配。
3. **复用最大风险？** 兼容迁移和停用状态在所有读取路径不一致。
4. **最小成本怎样验证？** 旧库迁移 fixture、停用泄漏测试、角色权限 API 测试和 20+20 查询集。
5. **证据是什么？** 20 条已执行报告、现有代码与新增自动测试/冻结报告。
6. **为什么选择 ADAPT？** 核心能力已达门槛，缺口集中且可在原边界内补齐。
7. **判断错误时怎样回退？** 回滚新增管理层和增量迁移，恢复原读取路径与数据库备份；不迁移至新向量库。
