## 3．本次历史版本功能的边界

复用已有Revision记录，优先补齐医生操作入口。建议首版支持：

1. 在当前病历打开版本列表，识别初始生成和后续保存记录。
2. 选择旧版本，查看该版本的七个病历字段及实际保存的元数据。
3. 与当前版本逐字段比较，分清新增、修改和未改变内容。
4. 关闭后返回当前病历，保留未保存编辑及既有审核状态。

首版不增加“覆盖为旧版本”、删除历史记录或撤销审核等写操作。只显示实际存储的信息；若旧记录缺少操作者或时间，不推测补造。实现完成仍需权限、快速切换、失败恢复和历史数据兼容验证，不把本计划当成功能已上线。

## 4．投入与优先级

10月20日至30日有9个工作日。按既有单人每日最多6h的限制，理论排期上限为54h，但尚未核实这9天的课程及其他工作占用，**不能直接视为54h可用时间**。

建议用于容量核对的上限为：功能与确定性缺陷14h、老师试用及定向修复10h、同版本验收14h、冻结与汇报材料4h，共42h；另预留最多12h处理失败与恢复。它是待验证的投入预算，不修改任务估算，不额外扩大总容量，也不是完成保证。实际占用和返工按事实记录到R11，不虚构既往净工时。

时间不足时，依次保留：

- **第一优先级**：历史版本可查看；输入、修改、保存、审核、导出及重开可靠；数据和权限不退化。
- **第二优先级**：老师能自行找到操作；知识来源可核对；失败有明确恢复路径。
- **第三优先级**：汇报材料、手册及已知问题与实际版本一致。

本窗口不增加新模型训练、第三个模型、药物方案、整套界面重构或硬件采购。知识目录保持已验证范围，查询相关性与来源完整性分别评价，不用文档数量替代效果。
