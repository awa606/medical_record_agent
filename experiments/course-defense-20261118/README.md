# MediListen 课程演示候选

## 11 月 26 日结课版

2026-11-24 的课堂包在 Windows 11 和 Debian 12 容器分别部署，两种操作系统共用一台物理电脑。最终运行清单 SHA-256 为 `5cc24fe0ff55c645447afbffe9adf3dbdf218f14b01482885e0fc7adce5128ee`。Linux 可直接用 Python 启动“课堂启动.py”。Windows 使用原双击入口。若同一端口的运行版本不同，启动器会提示使用对应版本的窗口或其他端口。

要逐字节重建上述课堂运行清单，使用维护仓库提交 `293f38e41b52e84ee4e081358c4a967f51308a7c` 或 `4de8ff18dd72d73c91174006294f16ae4b8ad385` 的源码，配合原冻结资产。后续维护版调整了医生字段抽屉，重建时会得到独立的候选运行清单。

两边各建一份空库，在一例固定合成问诊上核对全部 24 个首稿顶层字段和修订后字段，普通账号完成两次修订、分项确认、签署与 PDF 导出。两份 PDF 都标出 UTC+08:00，剔除各自实际就诊和导出时刻后，全文相同。此前 Windows 导出曾把两个时区的钟面并列显示，新版统一明确来源的时刻，历史缺少时区的信息保留标记。

每侧预热后采集三类读取各 30 次。队列、就诊详情、病历任务详情 P95 分别为 Windows 27.1、85.7、67.1 ms，Linux 10.5、29.0、18.2 ms。两边均通过预登记的小负载预算（每项 P95 ≤ 2,000 ms，跨平台绝对差 ≤ 250 ms）。首次功能基线的两项详情 P95 差超过 250 ms。固定字段树的脱敏读取曾打开 143 次 SQLite 连接；本版按需复用单次响应的一个读取连接，每个字段继续使用当时可见的身份映射核对。保留 JSON 类型与版本摘要。冻结材料使用独立构建补丁，工作目录中其他未提交的隐私研究修改不属于此配方。

医生从键盘进入病例导入后，焦点进入原文，Tab 在对话框内循环，Esc 返回原按钮。640×768 窗口中可读完四行原文并确认，首稿出现时清除上一阶段提示。已在 390、640、1366 像素宽做定向交互复核。本地交付包含课程评分对照与实际 Windows / Linux 原始数据，医院签署和现场评分由相应人员完成。

在准备好的各平台安装环境中，可执行 `verify_platform_replay.py <课程包> <合成核对动作.jsonl> <新结果目录>`。使用 `compare_platform_replays.py <Windows结果目录> <Linux结果目录> <报告路径>` 重新计算与核对。比较脚本需要 PyMuPDF。受授权限制的素材与模型首响应持续保存在本地。

本目录保存两个可独立复核的前端改动。完整课堂包、已保存的模型首响应和本机试用数据由资料持有者在本地管理。

### Windows 冷备迁往 Debian 后下载已签署文件

在 Windows 创建一份新的合成病例并修订到 R3，完成签署和第一次导出后关闭服务。将 SQLite 备份、签署文件和临时模拟账号恢复到无外网 Debian 容器的新目录，通过医生账号取回原 PDF。容器在恢复阶段只读取病历和文件。2026 年 11 月 24 日复验中，启动前 13 张表的行数一致，恢复前后 PDF 摘要相同，回执始终只有一条。两端位于同一台电脑，数据限于一例。脚本使用已固定摘要的运行包和本地镜像，已有凭据和真实就诊记录不参与复验。

在维护仓库根目录执行下列命令，交付根目录应包含“软件/现场回放”和“双平台/模拟核对动作.jsonl”。结果目录必须使用新路径。

```powershell
python experiments/course-defense-20261118/verify_cold_transfer.py --repo . --delivery "本次交付根目录" --out "本次复验新目录"
```

同轮后端另测一场 163.25 秒的合成中文问诊。首次真实转写对 548 字有 14 个替换。无角色判定时产品在角色环节阻断。把原始脚本和首次转写分别输入独立文字组件，各取一次首稿，七个核心栏目分别有 1 项和 6 项冲突。过敏史失真被拦截，另一处时间失真仍留在待核对稿。两份输出均未获医生批准。知识检索另测停用指南的页码定位，十个历史问题前五项命中 8/10 升到 10/10；两道难题的目标页仍分别位于第 4 和第 2。这些记录仅用于问题定位，临床放行和知识版本状态沿用现有门禁。

### 后续维护版的“查依据”入口

在普通医生的病历字段中点击“查依据”，已锁定的课堂版会显示来源卡片，却漏掉接口附带的医生人工核验提示。维护版在来源卡片之前保留接口的提示；查询结果为空时同时显示空态和提示。旧接口缺少提示时使用产品原有文案。相关规则保持原检索顺序，查阅不会自动写入病历。此改动单独走医生工作台回归，课堂投影包保留上述固定版本。知识服务在年龄未知或库内缺少适用指南时仍可能给出邻近来源。

### Windows 专用环境与离线首次启动

`windows-offline/` 保存随包目录“软件/专用环境”的启动源、3.14 文件锁和使用说明模板。发布准备时，原样放入该交付目录并保留相邻的“现场回放”。随包的 Windows x64 CPython 3.14.10 ZIP 通过官方发布摘要校验，28 个 wheel（27 个应用依赖及 pip）逐个保留发行摘要。需要重新取得文件时，解释器取自 Python 官方 [Windows 发行清单](https://www.python.org/ftp/python/3.14.10/windows-3.14.10.json)，轮包按锁定清单中的官方 PyPI 地址与 SHA-256 还原到 `wheels-win314-x64/`。小版本匹配、完整性检查与已验证运行包的身份按构建时的清单核对。

默认课堂入口在本机回环端口 26428 工作，独立于旧共享环境。2026 年 11 月 24 日，普通医生在新环境完成两次修订、批准和签署 PDF；与新启动的 Debian 部署对比，三类读取的 P95 最大差 79.7 ms（每端 90 次）。另以三个新的目录独立模拟首次开机，实际 .cmd 完成准备与登录。原 .cmd 从继承特定模块路径的 Windows PowerShell 启动时曾因找不到 Get-FileHash 而失败，入口改用 .NET 的 SHA-256 校验并在相同条件下通过。保留旧环境及故障记录。使用说明和实测使用固定合成病例。

构建器验证 158 项原始资产，复用维护分支的医生端及版本绑定导出接口，应用课堂界面补丁，填入已核验的合成问诊并生成运行文件清单。Git 仅在重建时使用。启动后可在本机 26418 端口的 `/course/identity` 查到 `classroom-review-2` 和运行清单 SHA-256。问诊和外部模型首响应保存在资料持有者本地。课堂程序只回放这份响应，支持真实的版本修订、审核和 PDF 下载。

## 早期投影版在 2026 年 11 月 18 日的验证

同一台 Windows 电脑上的 Anaconda Python 3.13.5 和独立 CPython 3.12.10 虚拟环境各自启动一份课程回放程序。两套程序目录、依赖目录、数据库和服务进程均独立。输入为同一例固定合成问诊，两侧健康与就绪检查均返回 200，24 个顶层结果键及完整字段树一致。每侧各回放一次，外部推理调用为零。

普通医生账号的浏览器角色走查覆盖登录、打开病历、查看原文、查询历史和进入编辑后返回。投影版在两种分辨率合计完成 20 次任务操作。另一次完整操作完成两处修订、版本保存、分项审核、实际 PDF 下载和刷新重开。首份草稿保留遗漏及字段混放，人工修订单独留存。该轮真实患者和独立医生参加人数均为零。软件结果限于课堂回放，正式 Alpha 项目仍按既有验收条件推进。
