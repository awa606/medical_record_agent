# 前端任务原型行为规范

本规范用于验证“病历正文为中心、需要时固定原文”的交互。对象是医生日常接诊；当前交付仅为两个固定合成病例的独立原型，不接入生产业务，不代替临床验证。

日期：2026-11-05。实现与运行结果由主线程另行记录；本文写成时尚未验收原型。

## 1. 范围与页面结构

- 仅在 `experiments/frontend-design-20261105/` 内验证设计，不修改生产页面、接口、数据库、模型或正式项目计划。
- 页面持续标明“交互原型 · 固定合成病例”。生成、连接中断、签署和导出均为演示状态；不得称真实模型生成、服务器保存、合法电子签名或正式病历导出。
- 仅使用内置 A、B 两个合成病例。文本框若允许编辑，其内容只参与本地交互测试；生成结果来自固定样例，按钮旁明确说明这一限制。不能把任意输入与固定输出说成真实推理。
- 录音和音频入口若在原型中出现，必须标明模拟输入，不调用麦克风、不读取用户私人文件、不发起 ASR 或外部模型请求。
- 主布局为任务列表、当前患者身份条、连续病历正文、单一主操作区。问诊原文可按需打开并固定在正文旁；诊疗参考按需查看，不常驻空白栏。
- 身份条至少显示病例名称与就诊编号；原文、编辑、恢复提示和导出回执均显示所属病例。不能依赖模糊的背景来判断输入归属。
- 本轮只用主诉、现病史、过敏史、诊断意见四个代表性字段，分为“病史、过敏、诊断”三个阅读区；章节按钮用于定位，不隐藏其余正文。生产中的查体、检查、既往史、用药与基本资料等字段保留在原系统，本轮不删除、不迁移，其完整布局待下一轮设计。

## 2. 固定病例与任务路径

| 病例 | 合成目的 | 必测内容 |
| --- | --- | --- |
| A | 有主诉、现病史和一项待处理信息的普通问诊样例 | 对照原文、改一个字段、明确处理异常、签署、导出、结束接诊 |
| B | 与 A 明显不同的否定或家属信息样例 | 检查主体区分、切换患者后输入为空或仅属于 B、独立保存与审核状态 |

两例使用固定输入与固定草稿。开发者在交付中公开样例内容及固定输出，不能在验证失败后换成更容易通过的病例。`A-1105`、`B-1105` 仅为测试哨兵，不是医疗事实。

完整操作路径：选择就诊 → 选择输入 → 载入合成输入 → 模拟生成 → 对照原文 → 修改字段 → 保存演示版本 → 处理异常 → 明确签署当前版本 → 导出合成示例 → 完成本次接诊。

输入方式变化不创建新患者；“下一位”回到任务列表，不能把当前文本沿用给下一位。已结束的病例仅能只读重开和下载既有快照；本原型不提供已结束病例重新编辑，生产重开流程待后续设计。

## 3. 状态与可用操作

状态按维度独立显示。连接成功不代表保存完成，草稿保存不代表已审核，文件生成不代表接诊结束。

| 维度 | 原型状态 | 页面含义与约束 |
| --- | --- | --- |
| 阶段 | 待接诊、采集信息、模拟生成中、核对病历、可导出、已结束 | 仅描述当前任务位置；已结束不自动新增病例 |
| 连接 | 演示连接正常、模拟中断、待恢复确认 | 正常仅代表模拟状态；中断时允许继续本地编辑，阻断模拟提交、签署和导出 |
| 保存 | 未开始、未保存、本页暂存、演示版本已保存、保存失败、发现可恢复内容 | “本页暂存”不能写成服务器保存；失败保留编辑；正式保存以显式按钮为准 |
| 审核 | 待核对、仍有异常、已选择待签署、当前版本已签署、修改后待重新签署 | 选择决定不等于签署；只有显式签署更新当前版本批准 |
| 导出 | 不可导出、可生成示例、示例已生成、下载已发起、下载失败 | 分清文件生成与下载发起；浏览器下载发起不等于文件已成功打开 |

当前任务只突出一个主操作：输入前为“开始输入”；输入就绪为“模拟生成草稿”；编辑中为“保存修改”；有待核对项为“核对病历”；全部决定完成为“签署当前版本”；已签署为“导出合成示例”；示例生成后为“完成本次接诊”。其他必要操作为次按钮。

生成完成后的正文即为可核对的初始演示版本；没有修改时不强迫医生先作无意义编辑才能审核。重新生成不能静默替换未保存内容或已经签署的版本。

### 原文与正文

- “对照原文”打开与当前病例绑定的原文，定位目标片段并显示关联字段。桌面核对状态允许原文与病历同时可见、分别滚动和操作。
- 固定原文时，点击字段不关闭正文；关闭原文后回到原触发控件，保留正文滚动位置与未保存修改。
- 窄窗口优先正文；原文和参考改为按需打开的辅助面板，提供清楚的“返回病历”。返回后保留原字段焦点、滚动位置及编辑内容。本轮不要求窄屏强制上下固定，同屏对照要求用于桌面布局。
- 只有真实音频样例才能显示音频时间。本轮文本样例显示“合成文本 · 无录音时间”，不得编造回放结果。

### 编辑、异常与签署

- 四个代表性字段供连续阅读核对；本轮重点演示缺失、冲突、诊断和风险四类明确决定。普通字段集中确认在生产中继续保留，本轮不完整迁移。不能默认确认所有异常，也不能用一个勾选消除证据冲突。
- 待核对摘要只承担定位作用；处理动作尽量靠近字段和原文，不要求反复回到页面顶部。
- “已选择，待签署”必须保持可辨认。签署前能复核或撤回选择；签署行为显示当前病例与保存版本。
- 签署仅绑定当前病例、当前保存版本和对应内容。输入、字段或有效审核依据变化后，旧签署不适用于新内容；编辑未保存时也不可导出旧批准为当前内容。
- 历史版本始终只读。查看旧版不覆盖正文、不自动恢复、不改变当前签署。

## 4. 离开、刷新与恢复

### 暂存边界

原型可使用 `sessionStorage` 暂存**本页合成演示数据**，仅覆盖当前浏览器标签页会话及刷新验证。按原型版本与病例编号分开命名，保存所属病例、基础演示版本、修改内容及未签署决定，不写真实身份、凭据、录音或外部资料。

这是交互 Spike 的临时手段，**不构成生产浏览器存储、加密、保留周期或患者数据方案的决策**。关闭标签页后不承诺恢复；存储不可用时明确提示“本页暂存不可用，刷新可能丢失修改”，不可继续展示暂存成功。

### 应用内离开

有未保存输入、未保存字段或未签署决定时，切换病例、回列表及结束接诊先显示具体提示，说明所属病例及未提交项目。提供三个可理解的选择：

1. **继续编辑**：取消离开，保留焦点及内容。
2. **暂存并离开**：仅本页暂存成功后离开，不签署、不覆盖保存版本。
3. **放弃本次未提交内容**：明确放弃后离开，原已保存版本保持不变。

普通查看原文、历史、参考无需触发离开提示，也不应丢失编辑状态。模态提示内按 Escape 等同“继续编辑”，不能悄悄放弃。

### 刷新和重新进入

- 原型在内容变化时尝试本页暂存，并在存在未提交内容时注册浏览器离开保护。浏览器是否显示原生确认由浏览器规则决定，不能把它作为唯一保稿措施。
- 刷新或回到存在暂存的病例，先显示“发现 A 的未提交内容”，给“恢复继续”和“舍弃暂存”两个明确动作；不自动恢复到 B。
- 恢复前验证病例、原型版本和基础保存版本匹配。恢复进入未保存/未签署状态，不改写保存版本、不恢复旧批准。
- 若基础保存版本变化，则并列展示保存版本与暂存内容，要求人工选择/核对；禁止静默覆盖。
- 模拟断连后，重连只恢复连接状态。未确认的提交不自动重发，未签署决定不自动批准。

## 5. 验收条件

- A 未提交输入关闭后切 B，B 不出现 A 的文本；A 的暂存只能由 A 明确恢复。
- 字段未保存时刷新、重开，能看见恢复提示并找回测试哨兵；拒绝恢复不改原保存版本。
- 已选择但未签署的决定离开时有提示，恢复后仍未签署。
- 修改已签署病例时，导出立即不可用；保存新版本后必须重新签署。
- 模拟失败保留当前内容；重复点击不会创建重复演示版本或隐式完成审核。
- 桌面固定对照状态下原文与正文同时可见；窄屏辅助面板可返回原字段，关闭面板不改变病历或患者。
- 模态框打开后焦点进入框内，Tab/Shift+Tab 不逃出，关闭返回触发点；普通状态更新不抢焦点。
- 两例均能通过可见按钮完成全部步骤；导出内容属于当前病例和当前签署版本，并明确标记合成示例。
- 结束接诊与导出分开；再次下载不会重新签署，也不会重新开始接诊。
- 记录真实步骤、操作数、区切换次数、耗时与失败，未测写 `NOT_TESTED`，不以源码或截图替代按钮验收。
