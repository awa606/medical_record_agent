## 本轮发现与修复复核

| 编号 | 发现与影响 | 修复与复核 |
| --- | --- | --- |
| PROTO26-01 | 结束临时编辑后，下一句曾自动清掉待合并状态，绕过显式合并 | `advance` 先判断等待合并；新增断言证明结束编辑后继续推进仍保持 `pending`，测试通过 |
| PROTO26-02 | 秒级整页重绘可能使重置确认框内容消失、详情自动折叠、标题焦点丢失 | 重置确认内容改为声明式分支；仅新句/派生变化重绘；保存详情展开和标题焦点键。静态确认，实际键盘仍待验 |
| PROTO26-03 | 保存后焦点目标仍指向旧版已删除字段按钮，审核后也可能失焦 | 保存返回整体编辑入口；审核后指向下一项/签署；签署后指向导出；结束接诊回主区。静态确认 |
| PROTO26-04 | 主诉固定来源遗漏 A 病例发热句；自填文本不适合套固定索引 | A 的来源包含第 2、4、6 句；自填内容退为完整输入原文并提示无固定映射。静态确认 |
| PROTO26-05 | 以导出数组非空判断当前版可模拟下载失败，可能操作旧版快照 | 当前版查找与 `exportId` 定向；没有本版快照时提示先导出。静态确认 |
| PROTO26-06 | `display:none` 覆盖隐藏标签，可能使编辑框没有可访问名称 | 删除覆盖，保留标准 `sr-only` 视觉隐藏。源码确认；实际可访问树待验 |
| PROTO26-07 | 空列表演示的筛选计数仍显示两例，与列表不一致 | 空状态计数归零。源码确认 |
| PROTO26-08 | 两例同时接诊时，列表的继续入口可能指向首个活动病例，而非当前选择的病例 | `home` 优先取处于 `active` 的 `s.currentId`，只有当前病例不在接诊中时才回退到其他活动病例；继续按钮的 `data-id` 与展示姓名均取同一 `active` 对象。定向静态复核通过 |
| PROTO26-09 | 生成任务断连时仍显示约 3 秒完成的承诺，与等待连接恢复的状态不一致 | `intake` 只在连接在线时显示 3 秒演示说明；非在线分支改为“连接恢复后继续获取当前任务结果”。定向静态复核通过 |

这些问题在实现过程中的初版被发现后修复；没有将静态推演声称为真实浏览器复现。

2026-11-06 追加定向复核仅覆盖 PROTO26-08 与 PROTO26-09 两处后改，并再次通过 `node --check`。核对 `capture.mjs`、`model.mjs` 与 `style.css` 指纹未变，因此保留上面的 44 项状态测试证据，不重复执行。本复核者的 GUI 项继续保持 `NOT_TESTED`；主线程另行完成的浏览器流程及其证据由 [design-qa.md](design-qa.md) 记录，不计为本独立复核者亲自执行。
